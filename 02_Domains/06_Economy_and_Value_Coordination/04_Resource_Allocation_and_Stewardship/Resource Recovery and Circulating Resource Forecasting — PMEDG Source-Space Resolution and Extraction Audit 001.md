# 4. R1 — Resource Recovery and Recirculation

## 4.1 Portable problem candidate

> **How can an object leaving its current use enter an accessible recovery path, be assessed before destructive routing, and be directed toward the highest reasonably viable remaining layer of value for productive re-entry without assuming central ownership, premature recycling or universal surveillance?**

## 4.2 Candidate mechanism

**Exit Event**
→ **Available Legitimate Entry Path**
→ **Collection / Transfer Interface**
→ **Safety / Data / Ownership Boundary Checks**
→ **Remaining-Value Triage**
→ **Candidate Recovery Routes**
→ **Highest Reasonably Viable Route**
→ **Productive Re-entry or Legitimate Residual Treatment**
→ **Outcome Evidence**

## 4.3 Inputs

Possible inputs:
- object/product/resource reference;
- current condition;
- current function/end-of-use state;
- available return/transfer routes;
- ownership/transfer state;
- safety/hazard constraints;
- data state where relevant;
- repair/reuse/component/material potential;
- provider/capacity availability;
- logistics constraints;
- provenance.

## 4.4 Outputs

Possible outputs:
- selected/available recovery route;
- retained value layer;
- receiving actor/interface;
- unresolved owner constraints;
- recovery outcome;
- residual treatment state;
- provenance/evidence.

## 4.5 Interfaces

External owners may supply:
- lifecycle disposition;
- ownership law;
- safety rules;
- privacy/data rules;
- component standards;
- transition integration;
- participant discovery;
- market matching.

R1 does not need to own them.

## 4.6 Failure modes

- waste-default routing;
- recycling too early;
- inaccessible nominal route;
- false recovery claim;
- unsafe convenience;
- data leakage;
- ownership overreach;
- monopoly capture;
- false component grading;
- logistics externality;
- capacity blindness.

## 4.7 Independence test

Can R1 operate without R2 forecasting?

**YES.**

An individual product can be returned, triaged and routed even if no civilisation-wide circulating-resource forecast exists.

Can R1 operate without Concord-specific Civil Contact?

**YES.**

A host can supply another discovery/interface mechanism.

Can R1 operate without LSR?

**YES.**

Ordinary end-of-use events can enter R1 without formal lifecycle review.

Can R1 operate without BTA?

**YES for low-complexity cases; external transition integration may be required for consequential cases.**

### R1 result

**INDEPENDENT CANDIDATE KERNEL ESTABLISHED FOR EXTRACTION PURPOSES.**

Not validated; not yet a portable specification.

# 5. R2 — Circulating Resource Forecasting

## 5.1 Portable problem candidate

> **How can a host estimate future recoverable supply from resources already embodied in products/assets, while distinguishing forecast from present inventory and avoiding unnecessary individual-object surveillance?**

## 5.2 Candidate mechanism

**Aggregate / Legitimate Asset and Product Data**
+
**Age / Retirement Distributions**
+
**Recovery Yield Evidence**
+
**Capacity Dependencies**
→ **Circulating Resource Estimate**
→ **Expected Future Recovered Supply**
→ **Uncertainty-Bounded Capacity / Resource Planning Input**
→ **Actual Outcome Comparison**
→ **Model Update**

## 5.3 Inputs

Possible inputs:
- resource class;
- product/asset class;
- quantity/stock estimate;
- age distribution;
- expected service life/retirement distribution;
- repair/reuse rates;
- expected recovery yield;
- region/service area;
- quality distribution;
- hazard state;
- recovery capacity;
- source confidence/provenance.

## 5.4 Outputs

Possible outputs:
- circulating resource estimate;
- expected recovered supply range;
- time window;
- location/region class;
- expected quality range;
- capacity dependency;
- confidence/uncertainty;
- provenance.

## 5.5 Failure modes

- surveillance creep;
- false precision;
- future-as-present inventory error;
- double counting;
- quality blindness;
- timing blindness;
- capacity blindness;
- strategic-hoarding error;
- central-planning capture.

## 5.6 Independence test

Can R2 operate without R1?

**YES, provisionally.**

A host can estimate future recoverable supply using historical recovery yields, external waste/recovery data, manufacturing cohorts or other legitimate sources even if it does not use R1's item-routing mechanism.

However, R1 can substantially improve R2 through actual outcome evidence.

Can R2 operate outside Concord?

**YES in principle.**

Municipalities, manufacturers, industrial systems, supply-chain planners or other hosts could model embodied future resource returns.

Does R2 inherently allocate resources?

**NO.**

It supplies evidence/forecasts.

### R2 result

**INDEPENDENT CANDIDATE KERNEL ESTABLISHED FOR EXTRACTION PURPOSES.**

Not validated; not yet a portable specification.

# 6. R3 — Combined Lifecycle Resource Loop

## 6.1 Candidate claim

R3 would combine R1 and R2 into one portable mechanism:

**Item Recovery**
→ **Aggregate Recovery Evidence**
→ **Forecast**
→ **Capacity Planning**
→ **Design Feedback**
→ **Future Recoverability**

## 6.2 Dependency test

Does R1 require R2 to perform its core function?

**NO.**

Does R2 require R1 to perform its core function?

**NO.**

Do they benefit from each other?

**YES.**

Does their feedback relationship justify one inseparable portable module?

**NOT ESTABLISHED.**

## 6.3 Failure of combined-boundary necessity

Combining them would force hosts needing only:
- item recovery

to import:
- forecasting architecture;

and hosts needing only:
- aggregate future resource forecasting

to import:
- item-level routing semantics.

That would enlarge the portable surface without demonstrated necessity.

> **Useful Feedback Between Mechanisms != One Indivisible Mechanism.**

### R3 result

**REJECT AS PRIMARY EXTRACTION BOUNDARY AT THIS STAGE.**

The combined loop remains valuable as a Concord composition and as an optional interface between R1 and R2.

# 7. Design-for-recovery boundary

Product design for disassembly/repair/upgrade/recovery is strongly related to R1 but is not necessarily part of R1's minimum operational mechanism.

R1 can recover poorly designed legacy products.

Likewise a product can be designed for recovery even where a particular R1 implementation is absent.

Therefore:

> **Design for Recovery Improves Recovery; It Is Not Identical to Recovery Routing.**

For portable extraction:
- R1 should consume available design/product information;
- R1 should emit recovery-outcome evidence;
- product design remains an external upstream/downstream interface unless later testing proves a necessary minimum field.

# 8. Accessibility boundary

Accessible return is part of R1 rather than merely a Civil Contact concern.

Reason:

A technically valid recovery process that participants cannot reasonably reach does not satisfy practical recovery.

Civil Contact is one Concord implementation of discovery.

But portable R1 requires the abstract function:

> **A legitimate recovery route must be practically reachable enough for the host's stated recovery claim.**

Candidate accessibility dimensions:
- route existence;
- discoverability;
- physical reachability;
- cost burden;
- time burden;
- handling burden;
- eligibility;
- safety compatibility;
- data compatibility;
- capacity state.

R1 need not impose one universal score.

---

# 9. Value-layer boundary

R1 requires a layered value concept sufficient to prevent premature destruction.

Candidate order is not universally rigid, but possible layers include:
- continued whole use;
- repair;
- upgrade;
- direct reuse;
- refurbishment;
- repurpose;
- component reuse/recovery;
- material recovery;
- residual treatment.

A higher layer is not automatically preferable if:
- unsafe;
- technically infeasible;
- environmentally worse across whole route;
- economically/resource irrational;
- legally unavailable;
- quality insufficient;
- no legitimate demand/capacity exists.

Therefore:

> **Highest Remaining Value != Highest Abstract Hierarchy Position Regardless of Context.**

The portable concept should be:

> **Highest Reasonably Viable Remaining Value.**

---

# 10. Authority boundary

Neither R1 nor R2 creates authority to:
- confiscate products;
- compel a particular provider;
- force OEM monopoly;
- expose private inventory;
- override safety;
- override environmental limits;
- command production;
- reserve future resources;
- represent forecasts as owned supply.

Host authority remains external.

---

# 11. ESCP audit

Potential missing dimensions include:
- hidden repair value;
- undocumented component compatibility;
- tacit industrial capability;
- external environmental cost;
- future scarcity;
- participant access barriers;
- data/security consequences;
- missing recovery capacity;
- cross-border restrictions.

Therefore R1 must not claim a globally optimal route merely from represented variables.

Candidate wording:

> **Selected Recovery Route != Demonstrated Globally Optimal Route.**

R2 likewise must preserve uncertainty:

> **Forecast Accuracy Within Represented Variables != Demonstrated Completeness of Future Resource Conditions.**
