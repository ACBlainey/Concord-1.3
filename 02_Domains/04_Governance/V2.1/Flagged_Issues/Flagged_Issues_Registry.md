# Governance V2.1 — Numbered Flagged Issues Registry

**Created:** 14 October 2026  
**Scope:** The 22 active V2.1 sectional manuscripts (Chapters 1–215) and the existing consolidated outstanding-issues register.  
**Purpose:** Number and locate work requiring resolution before V2.1 supersedes V2. This is a work queue, not a competing constitutional text.

## Conventions

- `FI-001` onward are stable sequential identifiers for this working registry. `G-001` through `G-027` retain their original cross-reference to the pre-existing central register; the remaining entries consolidate **section-local flags** from the 22-section scan.
- A flag is **not necessarily an undecided constitutional principle**: some concern implementation, evidence, source conflict, validation or a previously authorially settled rule whose remaining interface is not yet proven. Do not reopen settled direction without a real conflict.
- Historical `canonical` / `non-canonical` labels indicate writing-time currency, not completeness or precedence. V2.1 will supersede V2 after flagged issues are addressed.
- Work files belong here, keyed by `FI` number; decisions and corrections belong in the affected V2.1 chapters. Preserve source provenance and update `../Outstanding_Issues_Register.md` as appropriate.
- **Status:** all entries initially `Open / verify`; some have partially or substantively resolved architecture and require closure evidence, not reinvention.

## Resolution record requirements

For each issue record: the exact V2.1 chapter/paragraph, competing historical sources, authorial decisions already supplied, proposed rule or interface, remaining uncertainty, actual test/evidence if relevant, affected owner domains, and the section commit incorporating the resolution. Close only when those references exist. Where one issue overlaps another, cross-link rather than duplicate authority.
