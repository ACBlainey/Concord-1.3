# Existing Architecture Resolution Pass 002 — Authority, Review and Cross-Boundary Interfaces

**Date:** 14 October 2026  
**Basis:** Direct clause inspection of three existing Concord portable modules and comparison with the V2.1 flagged-issue crosswalk.  
**Disposition:** Reuse established source grammar; retain constitutional/owner-specific gates. **No issue is closed merely by identifying a module.**

## FI-004 / FI-018 / FI-021 / FI-022 / FI-024 — Multi-Key Authority

**Source:** `04_Portable_Modules/Multi-Key Authority — Portable Module v1.0.md`, §§17, 19, 21–23.

**Existing answers:**
- §17 prohibits composing individually legitimate authorities into a new authority without an independent composition basis. This directly addresses the V2.1 risk of a Steward majority, a resource owner and an execution host being treated as one transferable power.
- §19 explicitly represents independent-holder requirements without assuming that every function requires a different human decision-maker. Governance must specify its own Steward independence rule.
- §21 provides the useful emergency distinction **precompute the authority rule; verify the current facts**. An urgent lawful protective act need not wait for a fresh committee where its bounded authority is already legitimately activated.
- §22 says emergency urgency does not manufacture authority.
- §23 requires revalidation at consequential commit when act, route, target, context, consequence, time, authority source or protected interface materially changes.

**Proposed V2.1 reuse:** use MKA as the existing multi-owner consequential-authority composition and commit-time gate; use the V2.1 triadic architecture solely for the legitimate Steward decision event. Distinguish the vote result, host authorisation, each independent owner authority and effect receipt. **Remaining:** authenticated real owner claims, atomic/idempotent host commit and lawful constitution of the forum. Do not invent an overarching 'governance super-key'.

## FI-005 / FI-007 / FI-013 / FI-047 / FI-050 — State Triggered Review Architecture

**Source:** `04_Portable_Modules/State Triggered Review Architecture — Portable Module.md`, §§3–5, 9, 14, 18.

**Existing answers:**
- STRA separates trigger condition, review due, and substantive authority. §9 explicitly rejects a universal condition-satisfied → automatic substantive action inference; host automation requires a separate prior legitimate mandate.
- §14 supplies temporal backstops for stale or unobserved state triggers: material state/evidence/risk change **or** no later than time T. Backstops may target trigger definition, domain, routing or evidence rather than assuming one review actor.
- §18 distinguishes a repeated label, similar pattern and materially equivalent recurrence before reopening a case.

**Proposed V2.1 reuse:** STRA is a suitable review-due/expiry/revalidation trigger interface for emergency state machines and ordinary governance; it is not the Civilisation Clock itself, a substitute authority, or proof of real-time execution. **Remaining:** independently progressing emergency timebase, constitutional issuer/expiry rule, authenticated owner state feed, durable routing and actual expiry enforcement.

## FI-032 / FI-033 / FI-035 / FI-039 — Cross Boundary Externality Recognition

**Source:** `04_Portable_Modules/Cross Boundary Externality Recognition — Portable Module.md`, §§15–17.

**Existing answers:**
- §15 already distinguishes internal, shared/agreed, overlapping, disputed, absent and unknown authority, plus voluntary coordination, optional mediation and emergency contact.
- §16 requires the minimum response to be both effective and independently legitimate. Where no shared authority exists, actors may take separately lawful bounded actions or coordinate voluntarily without a new institution. The source calls this **PARALLEL-VOLUNTARY-COORDINATION**.
- §17 permits bounded scope expansion only upon demonstrated material dependency, recorded expansion and standing for newly affected parties, with no silent general authority.

**Proposed V2.1 reuse:** treat GTP spatial overlap/externality as a **recognition and routing event**, not automatic common jurisdiction or a superior spatial tier. A shared binding forum must derive from an independent lawful instrument; otherwise retain compatible independent local decisions. **Remaining:** constitutional competence creation, cross-resolution eligibility, nonparticipant rights, conflicting owners, thresholds and appeals.

## Synthesis and status

These sources already resolve the **general interface grammar** for several flags. They do not resolve V2.1-specific constitutional choices or deployment proofs. The strongest next action is to insert precise module cross-references in the relevant V2.1 chapters, replace contradictory ad hoc interface language where actually found, and then track residual decisions individually. The registry should distinguish **'existing source located'** from **'issue fully resolved'**.
