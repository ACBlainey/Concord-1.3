# Governance V2.1 — Flagged Issues Working Area

This folder holds working material created while investigating and resolving issues already flagged within Governance V2.1.

## Issue registry

- [Flagged_Issues_Registry.md](Flagged_Issues_Registry.md) is the numbered working queue, **FI-001–FI-083**, derived from a scan of all 22 V2.1 sectional manuscripts and the existing 27-item governance register. Preserve these FI identifiers in investigation files and resolution records.
- Existing `G-001`–`G-027` references are retained as cross-references; they are not alternative numbering for new work. Additional local flags are grouped to avoid creating dozens of near-identical implementation issues.
- This is an initial full-section flag inventory, **not a certified exhaustive contradiction audit**. Split or append issues when detailed clause review finds genuinely separate questions; never silently renumber established identifiers.

## Existing architecture recovery

- [Concord_Source_Recovery_Crosswalk_001.md](Concord_Source_Recovery_Crosswalk_001.md) records the initial cross-domain match between flagged issues and existing Portable Modules, Research development, Historical and Continuity sources. These are candidate reuse paths, not automatic issue closure.

## Working rules

- The authoritative location for an issue's substantive architectural resolution is its relevant V2.1 chapter section. This folder holds supporting analysis, comparisons, tests, evidence and resolution proposals, not a competing version of Governance.
- Use `../Outstanding_Issues_Register.md` as the consolidated issue index. Reference its existing issue ID in each work file; avoid creating parallel issue registers.
- Record the issue, affected V2.1 sections, source evidence, alternatives, decisions and remaining uncertainties. Once resolved, incorporate the agreed architecture directly into the affected V2.1 sections and update the central issues register.
- Treat historical canonical/non-canonical labels as writing-time currency markers, not proof of completeness or validation. Preserve older architecture where not substantively superseded.
- V2.1 is intended to supersede V2 once flagged issues are addressed and the architecture reconciled. Keep V2 intact for provenance.

Suggested file naming: `FI-001_Topic_Working_001.md` (using the actual issue ID and a descriptive topic). Supporting test files may be grouped into issue-specific subfolders as needed.
