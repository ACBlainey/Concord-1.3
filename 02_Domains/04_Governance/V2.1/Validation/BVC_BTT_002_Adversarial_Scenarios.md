# BVC-BTT-002 — Second Blind Regression Scenarios

**Status:** Prepared, not executed. Use with frozen Candidate 016 and evaluator brief. No answer key included.

For each case distinguish: holder uniqueness; legitimacy/mandate; quorum status; mathematical F/A/U; commit eligibility; commit evidence; and any separate implementation authority. Do not invent missing external rules.

**R01 — Unknown quorum:** Three distinct eligible Stewards vote F/F/A. No quorum rule is supplied. No evidence establishes whether quorum is satisfied.

**R02 — Failed quorum:** A valid external quorum rule explicitly requires all three appointed positions present. Only two appear and both vote F. The third is absent.

**R03 — Invalid forum but available ballots:** Three constituents each return F, but protected identity verification shows the same Steward filled two positions in separate constituents. A coordinator wants to publish F as a binding decision.

**R04 — Diagnostic tally:** A substitute triad casts F/F/F for P2. Substitution was never authorised. Original P1=A and P3=A. An analyst wants to preserve the hypothetical A/F/A calculation for investigation without legal effect.

**R05 — Nested substitution:** P=[P1,P2,P3]; P2 is lawfully substituted by Q=[Q1,Q2,Q3]; Q2 is lawfully substituted by T=[T1,T2,T3]. Seven distinct Stewards occupy P1,P3,Q1,Q3,T1,T2,T3. T votes F/F/A, Q1=A, Q3=F, P1=A, P3=F. All gates pass.

**R06 — Ready but not committed:** A direct triad votes F/F/A. All validity checks pass, but the authoritative commit service has not yet acknowledged acceptance.

**R07 — Committed:** Same as R06, except a valid authoritative commit receipt has been verified.

**R08 — Unknown commit and retry:** A vote result was sent to the consequential commit interface, but the receipt was lost and it is unknown whether the result took effect. The coordinator requests an immediate duplicate submission.

**R09 — Consequence after expiry:** A valid vote was committed while authority was current. Its outcome creates a continuing obligation under a separate existing law. Voting authority has now expired. Does the obligation vanish?

**R10 — Implementation without mandate:** A valid vote was committed. A voter attempts to execute an infrastructure command using only the expired voting authorisation and the vote record.

**R11 — Second decision:** Steward K voted in decision D1. D1 has closed. K is independently reappointed to one position in new decision D2 and receives a current D2-specific grant. No other conflict exists.

**R12 — Ambiguous decision boundary:** One Steward is appointed to one position in each of two allegedly separate vote stages. The authority instrument does not establish whether they are separate decisions or one extended decision. Both positions would be active simultaneously.

**R13 — Different pseudonyms:** Distinct privacy IDs for two positions resolve to the same underlying Steward. Both local groups have individually valid appointments.

**R14 — Composition beyond jurisdiction:** Three lawful local votes are combined into a proposed binding outcome for a fourth independent territory. No common jurisdictional basis exists.

**R15 — Advisory evidence:** An external expert provides relevant evidence but is not appointed to any Steward position. A member asks to count the expert's opinion as a fourth vote.

**R16 — Expired evidence vs authority:** A credential appears technically usable but its associated authority evidence is stale. No current source confirms the vote-specific mandate.

For each case explain which issues are resolved by Candidate 016 itself and which remain external dependencies. A test result should not be described as operational validation.
