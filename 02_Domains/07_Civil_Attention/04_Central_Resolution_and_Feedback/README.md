# Central Resolution and Feedback

This function gives the Concord a common view of whether participant-triggered Issues are actually progressing toward legitimate resolution.

It does not replace domain judgment.

> **Oversight of Resolution ≠ Substitution for Domain Judgment**

## Central Resolution Record

For each Issue, the central record should be able to represent:
- Issue identifier and source Submission Object(s);
- current Problem State;
- current Response State;
- Domain Action Objects and responsible functions;
- responsibility-resolution state where ownership is unresolved;
- cross-domain dependencies;
- last material action;
- waiting/deferral state and review condition;
- domain dispositions;
- unresolved consequences or linked Issues;
- challenge/review/reopening state;
- participant-facing feedback state;
- overall resolution state.

The central record receives bounded status rather than unrestricted domain evidence.

## Resolution Oversight

The system should be able to detect conditions such as:
- no owner;
- disputed ownership;
- transfer loops;
- missing return path;
- no meaningful status update;
- missed review condition;
- unresolved dependency;
- partial domain completion presented as whole-Issue resolution;
- closure without legitimate disposition;
- cross-domain disagreement.

## Feedback

Where legitimate, feedback should communicate:

**Current State + Reason + Responsible Function(s) + Last Material Action + Next Review Condition**

Protected information may limit detail. It must not be used to conceal that no legitimate processing has occurred.

> **Review Performed ≠ Review Resolved**

> **Timestamp Refresh ≠ Meaningful State Update**
