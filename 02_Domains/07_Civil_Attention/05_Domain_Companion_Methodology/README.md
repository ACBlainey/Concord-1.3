# Civil Attention Domain Companion Methodology

The Concord uses one graduated Civil Attention core across its domains.

Domain-specific requirements are appended through companion methodology. They do not create local rewritten versions of the core.

**Civil Attention Core Method v1.0 + Domain Companion + Bound Concord Services → Domain Implementation**

## A Companion May Define
- domain terminology and Issue taxonomy;
- legitimate domain owner(s);
- evidence and information requirements;
- confidentiality/protected-information handling;
- jurisdiction and authority boundaries;
- domain processing states;
- domain escalation routes;
- Civilisation Clock/review triggers;
- permitted dispositions;
- specialist interfaces;
- participant-feedback constraints;
- emergency or protective interfaces owned elsewhere.

## A Companion May Not
- redefine a core invariant;
- convert attention into command authority;
- remove original provenance;
- remove mandatory return;
- turn popularity into truth or substantive priority;
- centralise domain decision authority in Civil Attention;
- erase legitimate challenge/reviewability for convenience;
- silently modify the core method.

## Core Conflict Rule

If a domain discovers a genuine conflict or apparently universal improvement:

**Domain Finding → Core Review Candidate → Controlled Back-Propagation → Versioned Core Revision if Justified → Companion Regression Review**

Until that process completes, the domain preserves the current core.

> **Domain-Specific Need Is Evidence for Review, Not Permission for Drift.**
