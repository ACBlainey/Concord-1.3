# Mirrored Investigative Reality Trees — Evidence and Hypothesis Architecture 001

**Project:** The Concord  
**Domain:** Civil Security / Law / Judiciary / Research  
**Date:** 2 October 2026  
**Status:** ACTIVE DEVELOPMENT / BASIC INVESTIGATIVE ARCHITECTURE / PROVISIONAL / NON-CANONICAL

## 1. Purpose

This note develops a structured investigative method using mirrored Reality Trees.

Its purpose is to prevent an investigation from silently changing from:

> **What happened, and which explanation best fits the evidence?**

into:

> **How can enough evidence be found against the current suspect?**

The architecture treats a suspect as a hypothesis to test, not a conclusion to prove.

## 2. Core investigative principle

**Suspect != Conclusion**

**Investigation != Case Construction Against A Chosen Person**

**Evidence Collection != Search Only For Inculpatory Material**

Candidate principle:

> **The purpose of investigation is to determine which available explanation best fits the evidence, not merely whether sufficient evidence can be accumulated against the current suspect.**

## 3. Mirrored Reality Trees

For each material suspect/responsibility hypothesis, investigation maintains two linked trees.

### Inculpatory tree

Root proposition:

**Current Suspect / Hypothesis Is Responsible**

Branches contain evidence and intermediate propositions that support responsibility.

### Exculpatory tree

Mirrored root proposition:

**Current Suspect / Hypothesis Is Not Responsible / Current Suspect Hypothesis Is Wrong**

Branches contain evidence and intermediate propositions supporting non-responsibility, incompatible location/action, alternative explanation or another responsible actor.

The trees are evaluated together.

**Inculpatory Tree Alone != Complete Investigation**

## 4. Evidence states

Evidence may:
- support the inculpatory tree;
- support the exculpatory tree;
- support neither materially;
- bear on both in different ways;
- remain unresolved pending verification.

Therefore:

**Evidence != Necessarily Inculpatory Or Exculpatory**

A neutral/unresolved evidence state must remain available rather than forcing evidence into a preferred interpretation.

## 5. Evidence structure, not simple counting

The trees should expose:
- evidence quality;
- reliability;
- provenance;
- independence;
- corroboration;
- contradiction;
- dependencies;
- shared assumptions;
- evidential gaps;
- uncertainty.

A large number of derivative facts may all depend on one weak source.

Therefore:

**Evidence Count != Evidential Strength**

**Ten Dependent Indicators != Ten Independent Foundations**

Aggregate weighting may assist comparison, but the dependency structure must remain visible.

## 6. Aggregate support

The trees may produce aggregate indicators showing the relative support for competing propositions.

These indicators can assist:
- investigative direction;
- suspect-hypothesis review;
- evidential-gap detection;
- prosecution-threshold assessment;
- audit;
- later judicial understanding.

But:

**Tree Weight != Guilt**

**Tree Weight != Automatic Prosecution**

**Tree Weight != Authority**

The trees are decision-support and reasoning infrastructure.

## 7. Hypothesis review

A developing exculpatory tree can indicate that investigators are pursuing the wrong hypothesis.

Candidate states include:

### Both trees weak
Evidence remains insufficient. Continue legitimate investigation where justified or close where the investigative function no longer supports continuation.

### Inculpatory strong / exculpatory weak
Current suspect hypothesis receives substantial support and may be suitable for prosecution-threshold assessment.

### Both trees strong
Material contradiction exists. Further investigation, verification or independent adjudication may be required.

### Exculpatory strong / inculpatory weak
The current suspect hypothesis requires substantial reassessment and may need to be abandoned.

The purpose is not to force every case into these four states, but to expose when the current investigative direction is poorly supported.

## 8. ESCP and investigative hypothesis space

The Evaluation-Space Completeness Problem applies directly.

An investigation can fail even while reasoning correctly inside an incomplete hypothesis space.

Bad question:

**Did Suspect A Commit The Offence?**

Better question:

**What Happened, And Which Available Explanation Best Fits The Evidence?**

Candidate hypothesis space may include:
- Suspect A;
- Suspect B;
- unknown actor;
- multiple actors;
- no offence;
- accident;
- mistaken report;
- misidentification;
- system error;
- another explanation not yet represented.

Therefore:

**Correct Evaluation Of Wrong Hypothesis Space != Correct Investigation**

A strongly exculpatory tree should be capable of triggering expansion or reopening of the hypothesis space.

## 9. Alternative hypotheses

Where evidence weakens the current suspect hypothesis, the system should not merely record failure.

It should ask:
- which assumption failed?
- what alternative explanation becomes more plausible?
- does another participant or event fit the evidence?
- was the reported offence incorrectly characterised?
- is the investigation missing a class of explanation?

This creates:

**Contradiction -> Hypothesis Review -> Evaluation-Space Expansion Where Required**

rather than:

**Contradiction -> Search Harder For Supporting Evidence Against Existing Suspect**

## 10. Confirmation-bias resistance

The mirrored structure makes exculpatory investigation an ordinary part of investigation rather than an optional correction.

Investigators should actively test propositions capable of falsifying their current theory.

**Failure To Seek Reasonably Available Exculpatory Evidence -> Investigative Quality Concern**

This does not require endless investigation of every imaginable alternative.

ESCP is bounded by relevance, reasonable possibility, available evidence, proportionality and investigative resources.

## 11. Evidence classification provenance

Placement of evidence within a tree must be reviewable.

For material evidence, preserve where appropriate:
- evidence identity;
- provenance;
- evidential state;
- proposition supported or challenged;
- reasoning for placement;
- dependencies;
- reliability concerns;
- contradictory evidence;
- later reclassification.

Therefore:

**Evidence Classification != Investigator Preference**

Audit or another competent reviewer can reconstruct and challenge the tree.

## 12. Dynamic trees

The trees are living evidential structures.

New evidence may:
- strengthen a branch;
- weaken a branch;
- invalidate an assumption;
- create a contradiction;
- move an item from unresolved to supported;
- expose dependency;
- require a new hypothesis;
- collapse an existing hypothesis.

**Past Tree State != Current Evidential State**

This aligns with the prosecution rule:

**Material Evidence Change -> Threshold Reassessment**

## 13. Police operational value

Mirrored trees provide police with a diagnostic before prosecution is considered.

They help answer:

> **Are we even investigating the right suspect?**

This is upstream of:

> **Is there enough evidence to prosecute this suspect?**

Candidate sequence:

**Event / Report**  
-> **Open Hypothesis Space**  
-> **Candidate Explanations / Suspects**  
-> **Mirrored Reality Trees**  
-> **Evidence Continuously Tests Competing Hypotheses**  
-> **Weak / Contradicted Hypotheses Reassessed Or Abandoned**  
-> **Best-Supported Remaining Hypothesis / Hypotheses**  
-> **Prosecution-Threshold Assessment Where Applicable**

## 14. Interface with prosecution

The prosecution threshold receives the structured evidential state rather than merely an inculpatory case file.

The prosecution function can inspect:
- inculpatory support;
- exculpatory support;
- unresolved contradictions;
- dependency structure;
- evidential quality;
- alternative hypotheses;
- missing material evidence.

Therefore:

**Prosecution Referral != Presentation Of One-Sided Tree**

The mirrored structure operationalises the existing requirement that the prosecution threshold use the whole evidential state.

## 15. Interface with audit

Audit can evaluate both the event and the investigation itself.

Questions include:
- were material alternative hypotheses represented?
- was exculpatory evidence preserved?
- were contrary branches tested?
- was evidence improperly duplicated through dependent sources?
- were weak assumptions treated as established facts?
- was the suspect hypothesis retained after substantial contrary evidence?
- was the hypothesis space reasonably complete?
- did authority continue after the investigative basis materially changed?

This makes investigative reasoning itself reviewable.

## 16. Interface with Judiciary

Judiciary is not bound by police tree weighting.

The trees provide transparent reasoning/provenance rather than a verdict.

**Investigative Model != Judicial Finding**

Judiciary may reject:
- evidence classification;
- branch structure;
- assumed dependency;
- weighting;
- hypothesis completeness;
- reliability assessment.

## 17. Candidate safeguards

1. No guilt inference merely from being represented as a suspect hypothesis.
2. Exculpatory evidence receives equal provenance protection.
3. Neutral/unresolved evidence is not forced into either side.
4. Aggregate scores cannot conceal dependencies.
5. Alternative hypotheses remain available where reasonably supported.
6. Investigators cannot delete contrary evidence by abandoning a branch.
7. Tree history should remain auditable where legally required.
8. Automated assistance cannot convert model confidence into legal authority.
9. A high inculpatory score cannot itself create search, detention or prosecution authority.
10. A strong exculpatory state must be capable of contracting investigative authority directed at that suspect.

## 20. Compact architecture

**What Happened?**  
-> **Represent Reasonable Hypotheses**  
-> **For Each Material Suspect: Inculpatory Tree + Exculpatory Tree**  
-> **Map Evidence / Provenance / Dependencies / Contradictions**  
-> **Continuously Compare Competing Explanations**  
-> **Reassess Or Abandon Weak Suspect Hypotheses**  
-> **Expand Hypothesis Space Where Required**  
-> **Advance Supported Hypotheses To Evidential Sufficiency Assessment**  
-> **Independent Prosecution Threshold**  
-> **Independent Judiciary**

In compact form:

> **Investigate the explanation, not the suspect.**


## 21. PMEDG candidate status

**PMEDG CANDIDATE / DO NOT EXTRACT YET**

The investigative implementation should first be stress-tested against varied cases. If the method remains stable, the portable extraction should generalise the reasoning pattern rather than merely reproduce the policing implementation.

Candidate portable core:

**Question**  
-> **Candidate Hypothesis Space**  
-> **Mirrored Reality Trees**  
-> **Map Supporting / Opposing / Neutral / Unresolved Evidence**  
-> **Expose Dependencies And Contradictions**  
-> **Compare Competing Hypotheses**  
-> **Test Whether The Hypothesis Space Is Complete**  
-> **Reformulate The Question Where Required**  
-> **Repeat**

The higher-order Blaineyan Reasoning contribution is not simply weighing competing answers. It is the recursive test:

> **Are these the correct propositions to be testing, or has the question itself constrained the answer space incorrectly?**

Therefore:

**Well-Formed Reality Tree != Correct Root Question**

**Strong Reasoning Inside Incomplete Evaluation Space != Complete Reasoning**

**Contradiction / Poor Fit -> Test Hypothesis Space -> Potentially Reformulate Root Question**

The policing implementation remains the current worked application and validation environment. Portable extraction is deferred until that implementation has been stress-tested.
