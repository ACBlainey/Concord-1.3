# 1. Purpose

Relational Grammar v1.0 defines the first frozen structural rule set to be used prospectively for whole-V1.2 topology and gap detection.

It is not a constitution.

It is not a replacement for U1–U8, Blainey's Laws, source reasoning or participant judgement.

It is a diagnostic formalisation of recurrent architectural relations observed across multiple Concord domains and scales and supported by a first out-of-sample test.

# 4. Gap Types

The grammar authorises detection of candidate gaps in the following classes.

### H-E — Ethical/Constraint Gap

A consequential function has no verified path to a relevant ethical constraint.

### H-F — Functional Gap

A required function is recognised but no architecture is verified as supplying it.

### H-B — Boundary Gap

A consequential capability/authority exists without a verified scope boundary.

### H-P — Participant Gap

A materially affected participant lacks a verified standing/agency/challenge path.

### H-A — Asymmetry Gap

Material asymmetry exists without a verified anti-domination safeguard.

### H-C — Correction Gap

A consequential system/failure has no verified review→correction path.

### H-T — Temporal Gap

An authority or architecture has no verified revision/contraction/exit/replacement path.

### H-D — Dependency Gap

A critical function depends on a component with no verified alternative/recovery route.

### H-L — Learning/Provenance Gap

Correction or failure occurs without a verified path into provenance and learning.

### H-R — Recursive Gap

A meta-system imposes a relevant constraint on others but lacks a verified equivalent constraint on itself.

### H-G — Generative Gap

A recognised need/capability gap lacks a verified path into candidate generation, testing and adoption.

### H-M — Machine-Representation Gap

A consequential civilisational object lacks a verified machine-readable representation or translation/provenance path where such representation is required for substrate-neutral access.

# 5. Candidate-Hole Algorithm

For each node (x):

1. identify type;
2. identify function;
3. identify affected participants;
4. identify authority/capability;
5. identify dependencies;
6. identify failure modes;
7. activate applicable grammar rules;
8. enumerate expected outgoing/incoming relations;
9. compare expected relations with verified graph;
10. mark missing relations as **candidate holes**;
11. search source corpus;
12. classify each candidate:

[
CandidateHole
ightarrow
egin{cases}
RepresentationGap\
DistributedExistingFunction\
PartialArchitecture\
GenuineStructuralGap\
Undetermined
end{cases}
]

No candidate may be called a genuine gap before Step 12.

# 6. Deriving a Missing Function

For a verified structural gap (h), define its local neighbourhood:

[
N(h)={predecessors,successors,constraints,participants,dependencies,failures}.
]

Infer the missing functional specification:

[
Spec(h)=
{
Purpose,
Inputs,
Outputs,
Constraints,
Interfaces,
Standing,
Review,
Correction,
Exit,
Provenance
}.
]

Then generate candidate implementations:

[
A_h={a_1,a_2,ldots,a_n}.
]

Each candidate must satisfy:

[
a_imodels RelevantEthics
]

and:

[
a_imodels ApplicableGrammar
]

and must survive failure analysis sufficiently to remain a candidate.

The topology derives the **required function and constraints**.

It does not uniquely determine implementation unless the evidence actually constrains the solution to one form.

# 8. ESCP and Anti-Circularity

This grammar is incomplete by default.

[
Grammar_{v1.0}
eq CompleteCivilisationalTruth.
]

A system may be structurally necessary even if v1.0 cannot predict it.

A relation may matter even if the ontology cannot encode it.

Unexpected evidence should be allowed to alter the grammar in later versioned releases.

v1.0 is frozen so that future gap detections can be evaluated against a stable rule set rather than changing the rules after seeing the result.
