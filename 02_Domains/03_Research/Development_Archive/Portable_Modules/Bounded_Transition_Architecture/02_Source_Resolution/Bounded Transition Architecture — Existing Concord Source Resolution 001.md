**Author:** Alexander C. Blainey — Independent Researcher  
**Project:** The Concord Framework

**Status:** ACTIVE DEVELOPMENT / SOURCE RESOLUTION / NON-CANONICAL  
**Date:** September 2026

---

# 1. Purpose

Determine whether the emerging Bounded Transition / Successor-State architecture is genuinely missing from Concord, or whether existing architectures already collectively contain it.

This source resolution compares the candidate against:
- State and Maturity Mapping (SMM);
- Knowledge Control System (KCS) dependency/change-propagation architecture;
- Civilisation Clock consequence-relevant state-transition layer;
- Contextual Wrapper Architecture (CWA);
- the prior lifecycle/successor-state recurrence study;
- the cross-domain adversarial test;
- three subsequent sketches: Utilities, Culture and Biological Participant Genomic Custody.

ESCP rule:

> **Do not classify an integration gap as a missing architecture until the surrounding source systems have been resolved.**

---

# 2. Candidate problem

The emerging problem is not simply:

> What state is this object in?

Nor:

> What depends on this object?

Nor:

> What context applies?

Nor:

> What development transition occurred?

The candidate problem is:

> **How should a consequential change from one scoped state/configuration to another be represented so that the transition itself remains explicit: its trigger, legitimate basis, constraints, cardinality, surviving duties/value, terminated permissions/authority, released resources, dependencies, provenance, reversibility and resulting state(s)?**

---

# 3. State and Maturity Mapping

SMM owns current developmental-condition representation:
- presence;
- maturity;
- context-relative sufficiency;
- dependencies/blockers;
- active work;
- evidence/provenance/freshness;
- unresolved state.

It explicitly establishes:
- State Vector != Universal Score;
- State Description != Permission;
- Current State != Erasure of Prior State.

## Overlap

SMM strongly supports:
- multidimensional state;
- context/scoping;
- uncertainty;
- provenance;
- state history.

## Boundary

SMM is principally a **self-model of developmental condition**.

It does not generally own:
- the legitimate transition event between arbitrary operational states;
- transition authority;
- surviving duties;
- authority termination;
- resource release;
- branch/merge transition cardinality;
- transfer restrictions.

**Finding: COMPLEMENTARY, NOT DUPLICATE.**

> **SMM Describes State; BTA Candidate Describes Consequential State Change.**

---

# 4. KCS dependency/change propagation

KCS owns knowledge/dependency relationships and propagation of consequential change through dependent architecture.

It can identify:
- changed source;
- dependent objects;
- required review/update;
- provenance;
- unresolved propagation.

## Overlap

KCS strongly supports:
- dependency resolution;
- propagation after change;
- version/supersession;
- correction;
- downstream consequence.

## Boundary

KCS does not by itself define a universal transition object for:
- physical resource flow;
- permission expiry;
- enterprise retirement;
- utility injection;
- custody transfer;
- contextual activation;
- branch/merge of non-knowledge objects.

**Finding: COMPLEMENTARY.**

> **KCS Answers What Must Be Reconsidered Because Something Changed; BTA Candidate Represents the Change Event and Its Bounded Consequences.**

BTA should invoke KCS where dependencies exist rather than duplicate propagation logic.

---

# 5. Civilisation Clock transition layer

The Civilisation Clock extension already represents consequence-relevant state transitions and can preserve branch-aware developmental topology.

This is the closest existing source.

## Overlap

Strong overlap:
- transition relations;
- consequence relevance;
- branch-aware topology;
- prior/next state relationships;
- civilisational developmental sequence.

## Boundary

The Clock's purpose is civilisational developmental topology/time.

It does not appear to own general operational transition semantics such as:
- who legitimately authorises the transition;
- permission/authority termination;
- custody transfer;
- resource release/recovery;
- surviving legal/ethical duties;
- data-purpose constraints;
- continuous resource flows.

**Finding: CLOSE NEIGHBOUR / NOT FULL DUPLICATE.**

BTA must not recreate Clock topology. Where a transition is civilisationally consequential, the Clock can receive/reference the transition relation.

---

# 6. Contextual Wrapper Architecture

CWA is another close neighbour.

CWA owns:
- bounded context representation;
- activation;
- nested/overlapping contexts;
- functional permissions;
- authority bounding;
- context termination/reversion;
- residual-state termination;
- external dependencies;
- unresolved conflict;
- representation divergence.

## Overlap

Very strong overlap in:
- scope;
- context;
- permissions;
- authority;
- termination;
- reversion;
- unresolved state.

## Boundary

CWA's portable problem is **bounded contextual variation**.

A product becoming component feedstock, an enterprise winding down, a genome moving from clinical custody to restricted research, or a utility flow crossing a quality gate need not be a contextual-wrapper problem.

**Finding: COMPLEMENTARY WITH SIGNIFICANT SHARED GRAMMAR.**

> **CWA Describes the Bounded Context and Its Rules; BTA Candidate Describes a Consequential Transition Across or Within States/Contexts.**

BTA must reuse CWA where transition crosses a context boundary.

# 7. Existing continuity/accountability architecture

Fault-Tolerant Accountability already represents:
- primary;
- concurrent;
- successor-ready;
- transfer-pending;
- successor-active;
- no-valid-successor;
- safe-state;
- retirement.

This independently confirms that transition state matters.

But its portable function is responsibility continuity.

**Finding: DOMAIN-SPECIFIC INSTANCE OF THE BROADER GRAMMAR, NOT DUPLICATION.**

# 9. Utility sketch contribution

The Utilities sketch materially expands the evidence.

A utility node can simultaneously:
- consume;
- produce;
- store;
- process;
- import;
- export;

across different resources.

A resource may be:
- physically available;
- locally usable;
- below distribution grade;
- eligible for treatment intake;
- prohibited from final-network injection.

This is **not a lifecycle/succession problem**.

It is continuous bounded state transition.

Therefore Utilities falsifies any interpretation that the candidate architecture is merely “planned retirement”.

> **Bounded Transition Grammar Applies to Continuous Operational Flow as Well as Lifecycle Change.**

It also adds an interface concept:

`Prior Resource State + Interface/Quality Gate + Validated Transition -> Next Resource State`

This resembles CWA/Interoperability Wrapper but concerns state-bearing flow.

---

# 10. Culture sketch contribution

Culture adds a different topology.

A cultural work may:
- be created;
- published;
- distributed;
- withdrawn from current distribution;
- remain in sold copies;
- have lawful derivatives;
- remain historically recorded;
- be republished/reissued;
- have disputed attribution.

This establishes:

> **Withdrawal From Current Distribution != Erasure of Historical Existence.**

Culture also demonstrates that different dimensions can transition under different authorities:
- creator controls future publication where legitimately theirs;
- Historical may retain bounded provenance;
- Commerce may retain completed transaction records;
- third parties may possess legitimate copies;
- derivative rights may differ.

**Contribution: transition authority is dimension-specific.**

> **Authority to Change One State Dimension != Authority to Change Every Related State Dimension.**

---

# 11. Genomic sketch contribution

The Biological Participant Genomic Custody sketch is the strongest authority-transfer test.

Objects can transition:
- physical sample;
- genomic sequence;
- clinical record;
- research dataset;
- derived result;
- Historical provenance.

But:

> **Sample Custody != Genomic Data Custody != Research Dataset Custody.**

and:

> **Consent to One Genomic Function != Consent to Every Genomic Function.**

This exposes a critical invariant absent from the original lifecycle formulation:

> **Object Transition Does Not Automatically Propagate Authority, Consent or Purpose.**

A genome can move into Historical custody without Historical acquiring:
- collection authority;
- clinical authority;
- unrestricted research authority.

A research dataset can be derived without inheriting every permissible use of the source.

Therefore BTA requires explicit **non-propagation semantics**.

# 12. New candidate transition dimensions

The combined evidence suggests that a transition record may need to distinguish:

1. **Object/function identity**
2. **Scope/context**
3. **Prior state vector**
4. **Trigger**
5. **Transition cardinality** — 1→1, 1→many, many→1, many→many, 1→none, unresolved
6. **Legitimate transition basis/authority**
7. **Consent/purpose state where applicable**
8. **Interface/gate conditions**
9. **Next state vector(s)**
10. **Surviving duties**
11. **Surviving value/capability**
12. **Terminated permissions/authority**
13. **Released/recovered resources**
14. **Dependencies requiring propagation**
15. **Historical/provenance state**
16. **Reversibility/rollback state**
17. **Uncertainty/dispute**
18. **Non-propagating attributes**

---

# 13. Candidate transition object v2

`BoundedTransition = <TransitionID, ObjectOrFunctionRef, Scope, PriorStateVector, Trigger, Cardinality, TransitionBasisRef, ConsentOrPurposeState, InterfaceGateRefs, NextStateVectorRefs, SurvivingDutyRefs, SurvivingValueRefs, TerminatedAuthorityRefs, ReleasedResourceRefs, DependencyRefs, Provenance, ReversibilityState, UncertaintyOrDisputeState, NonPropagationRules>`

This is deliberately a grammar, not a sovereign decision engine.

---

# 14. Non-propagation rules

The new sketches make this necessary.

Candidate:

`NonPropagationRule = <SourceAttribute, TransitionClass, DestinationScope, PropagationState, IndependentAuthorityRequired, Provenance>`

Examples:
- clinical consent → research use: **DO_NOT_PROPAGATE / independent consent or authority required**;
- emergency authority → Historical record: **DO_NOT_PROPAGATE**;
- creator publication permission → Historical preservation: **DO_NOT_ASSUME EITHER DIRECTION**;
- utility resource ownership → quality verification: **ownership does not transfer merely because quality is verified**;
- enterprise functional succession → liability: **DO_NOT INFER**.

> **Transition of the Object != Transition of Every Attribute Attached to the Object.**

This is a substantive addition from the combined work.

# 15. Dimension-specific transition authority

Culture and genomics expose another refinement.

An actor may legitimately change:
- publication state;

without authority to change:
- Historical retention state.

Health may change:
- clinical interpretation;

without authority to change:
- research-consent state.

Infrastructure operator may change:
- operational state;

without authority to extinguish:
- surviving remediation duties.

Therefore:

> **Transition Authority Must Be Scoped to the State Dimension Being Changed.**

Candidate:

`TransitionAuthority = <ActorOrProcessRef, StateDimension, Function, Scope, Basis, EffectiveTime, Conditions, Termination, Provenance>`

BCA should supply the authority semantics; BTA only references them.

---

# 16. Interface-gated transitions

Utilities adds a class not explicit enough in the prior work.

Some transitions are legitimate only if the object satisfies an interface condition.

Examples:
- electricity may enter grid only within required electrical conditions;
- water may enter potable network only after required quality state;
- recovered component may enter reuse market only after required safety/grade;
- research output may leave controlled genomic environment only after disclosure review.

Therefore:

> **Possession of an Object != Eligibility to Cross an Interface.**

Candidate sequence:

**SOURCE STATE**
→ **INTERFACE GATE**
→ **VALIDATION**
→ **TRANSITION**
→ **DESTINATION STATE**

CWA/Interoperability architecture can own interface meaning; BTA records the transition relation.

---

# 17. Transition versus propagation

A critical boundary:

## Transition
Changes the state/configuration/location/context of the object/function.

## Propagation
Re-evaluates other objects because that transition matters to them.

Therefore:

**Transition event**
→ **recorded by BTA grammar**
→ **dependency references exposed**
→ **KCS/change-propagation invoked**
→ **dependent objects reviewed**

> **Transition != Dependency Propagation.**

This avoids absorbing KCS.

---

# 18. Transition versus state mapping

Likewise:

**SMM**
asks:
> What is the represented developmental state now?

**BTA**
asks:
> What bounded consequential change occurred/is proposed, under what basis, and what survives/terminates/propagates?

BTA may consume/produce state vectors but should not own maturity assessment.

---

# 19. Transition versus context

**CWA**
asks:
> What bounded context applies, and what differs here?

**BTA**
asks:
> What consequential state change crosses/occurs within that context?

A transition may activate/deactivate a wrapper.
A wrapper may constrain a transition.

Neither should absorb the other.

---

# 20. Transition versus Civilisation Clock

**Civilisation Clock**
asks:
> What civilisational/developmental state transition occurred and how does it sit in developmental topology/time?

**BTA**
asks:
> What are the bounded semantics of the transition itself?

Consequential BTA transitions may become Clock events.

Routine utility flows normally should not.

---

# 21. Does the candidate add machine-readable value?

Yes, conditionally.

Without a transition object, existing systems can represent:
- before state;
- after state;
- context;
- dependencies;
- provenance.

But they do not consistently require a single machine-readable relation containing:
- legitimate transition basis;
- explicit terminated authority;
- surviving duties;
- non-propagating permissions/consent;
- cardinality;
- rollback;
- interface gates.

The sketches make these omissions operationally important.

Therefore the candidate appears to add genuine value as an **integration grammar**.

---

# 22. What the candidate must not become

BTA must not become:
- a universal workflow engine;
- a global event log;
- a substitute for CWA;
- a substitute for KCS;
- a substitute for SMM;
- a substitute for the Civilisation Clock;
- a decision authority;
- a rights engine;
- a universal legal succession engine;
- a requirement to formally model every trivial change.

Use should scale with consequence.

> **Consequential Transition Architecture != Bureaucratisation of Every State Change.**

---

# 23. Materiality gate

Candidate use rule:

A formal BTA record is warranted where a transition materially affects one or more of:
- rights/standing;
- authority/permission;
- responsibility/duty;
- safety;
- custody;
- scarce/significant resources;
- continuity;
- consequential dependencies;
- irreversible state;
- Historical accountability;
- sensitive purpose/consent;
- cross-system interoperability.

Routine low-consequence state changes can remain local.

---

# 24. Source-resolution conclusion

The emerging architecture is **not already present as one existing Concord module**.

Nor is it wholly new.

Its components are distributed across:
- SMM;
- KCS;
- Civilisation Clock;
- CWA;
- BCA;
- Fault-Tolerant Accountability;
- Historical;
- Infrastructure lifecycle;
- Commerce/resource lifecycle.

The genuine missing element is the **integration grammar for consequential bounded transitions**.

The three new sketches materially strengthen this conclusion:

### Utilities
shows BTA is not merely lifecycle/succession; it applies to continuous resource-state transitions and interface gates.

### Culture
shows one object can have independently changing publication, ownership/access and Historical states, under different legitimate authorities.

### Genomics
shows object movement/derivation must not silently propagate consent, purpose, authority or correlation permission.

---

# 25. Candidate kernel

> **For a consequential bounded transition, identify the object/function and scope; represent the prior state; identify the trigger and legitimate transition basis; apply required interface/consent/purpose constraints; represent the resulting state or state topology; explicitly preserve surviving duties/value/provenance; explicitly terminate authority/permissions that no longer apply; prevent attributes that require independent legitimacy from silently propagating; expose dependencies for separate propagation; and preserve rollback, uncertainty or unresolved state where materially relevant.**
