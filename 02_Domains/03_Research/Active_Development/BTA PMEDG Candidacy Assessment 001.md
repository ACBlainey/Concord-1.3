# BTA PMEDG Candidacy Assessment 001

**Candidate:** Bounded Transition Architecture (BTA)
**Project:** The Concord Framework
**Framework Version:** Concord V1.3
**Method:** Portable Module Extraction, Development and Graduation Method — PMEDG v1.2
**Status:** PMEDG CANDIDACY ASSESSMENT / ACTIVE DEVELOPMENT / NON-CANONICAL
**Date:** September 2026

# 1. Question

Has BTA developed far enough to enter formal PMEDG portable-module extraction, or should it remain ordinary Active Development?

This is not a graduation review. It determines whether formal portable extraction is now justified.

# 2. Candidate function

BTA provides a common integration grammar for consequential transitions across independently owned, multidimensional and potentially asynchronous state systems.

Its residual function after source resolution is:

> **Provide a common transition-coherence contract through which independently owned state machines can participate in one consequential bounded transition without losing state, authority boundaries, pending obligations, non-propagation rules, provenance, recovery position or legitimate ownership of substantive semantics.**

# 3. Candidate level

**Recommended PMEDG entry level: LEVEL B — EXTRACTABLE ARCHITECTURE.**

Reason:

- BTA is already a coherent reusable architecture;
- its portable kernel is visible;
- it remains embedded in Concord-specific owner names and source relationships;
- portability requires replacing Concord-specific owner references with generic interfaces without erasing provenance;
- it is larger than a primitive mechanism but not yet a standalone portable specification.

# 4. Source-space readiness

Source resolution has already examined BTA against major neighbouring architectures, including:

- Civil State Handover Protocol;
- KCS Change Propagation;
- State Triggered Review Architecture;
- Cross Boundary Externality Recognition;
- Civilisation Clock / CRSTL;
- Fractal Permission / authority architecture;
- Continuity Protocol;
- Historical;
- Infrastructure transition architecture;
- enterprise wind-down;
- genomic/data-purpose transition;
- clean Constitutional Emergency architecture.

Three explicit source-resolution records progressively narrowed BTA rather than expanding it.

**Assessment: SUFFICIENT TO BEGIN FORMAL PMEDG SOURCE RESOLUTION.**

PMEDG should still create its own formal Source Resolution and Extraction Audit rather than treating prior development records as a substitute.

# 5. Kernel stability

Across adversarial tests and source resolution, several apparent BTA functions were correctly returned to existing owners:

- consequence horizon → CBER;
- dependency propagation → KCS;
- validation criteria/review → STRA/domain validators;
- transition ordering/ancestry → Clock/CRSTL;
- permission/authority semantics → FPA/BCA/legitimate authority systems;
- recovery sufficiency → Continuity/domain;
- Historical custody/reconstruction → Historical;
- specialised civil handover semantics → CSHP.

What remained was transition coherence/interoperability.

Subsequent clean-domain and blind machine-readable testing did not require restoration of those removed functions.

**Assessment: KERNEL STABLE ENOUGH FOR EXTRACTION.**

# 6. Boundary integrity

Interface-Boundary Audit 004 found no material owner-system absorption.

BTA now explicitly states:

> **Reference to an Owner-System State Does Not Transfer Ownership of That State's Semantics to BTA.**

and:

> **BTA May Bind, Preserve and Compare Scoped Owner-System States; It Must Not Manufacture, Override or Resolve Those States Unless a Separate Legitimate Owner Explicitly Supplies That Function.**

**Assessment: PASS FOR CANDIDACY.**

# 7. Proportionality

Materiality Test 005 showed:

- routine local change → no BTA event;
- simple consequential change → compact minimum record;
- moderate multi-owner transition → incremental interface expansion;
- high-consequence transition → fuller contract.

BTA therefore does not require maximal architecture for every change.

**Assessment: PASS FOR CANDIDACY.**

# 8. Transfer evidence already available

BTA has evidence beyond what is normally required merely to enter PMEDG:

- adversarial tests 001–004;
- clean cross-domain Constitutional Emergency test — PASS;
- blind machine-readable transfer test — PASS with strong structural convergence;
- interface-boundary audit — PASS;
- materiality/proportionality test — PASS.

However, the existing blind test is not a substitute for PMEDG Blind Transfer Tests 001 and 002 because PMEDG requires testing the **standalone portable specification** in materially non-Concord scenarios.

**Assessment: STRONG PRE-PMEDG EVIDENCE; FORMAL PORTABLE TESTS STILL REQUIRED.**

# 9. ESCP discipline

BTA preserves the distinction between represented transition coherence and completeness of the evaluation space.

It does not claim that a correct BTA record proves every materially relevant dimension has been represented.

Materiality Test 005 further adds:

> **Small Represented Transition != Demonstrated Small Real Consequence.**

**Assessment: PASS FOR CANDIDACY.**

# 10. Portability hypothesis

The portable problem can be stated without Concord:

> **How can independently owned systems coordinate one consequential transition when different state dimensions may change asynchronously, without allowing completion, authority, permission, responsibility, validation or recovery in one dimension to be silently inferred in another?**

Candidate portable kernel:

1. stable bounded transition identity and scope;
2. references to participating independently owned state dimensions;
3. scoped prior/current/next transition state;
4. explicit pending/intermediate/unresolved state;
5. completion conditions supplied by legitimate owners;
6. non-propagation rules between consequential dimensions;
7. surviving duties and terminated authority where material;
8. external dependency/externality/validation/recovery references where material;
9. failed/partial-transition provenance and residual effects;
10. minimum-sufficient representation proportional to consequence;
11. owner-system non-absorption;
12. ESCP-aware completeness boundary.

This kernel does not require adoption of Concord.

**Assessment: PORTABILITY PLAUSIBLE.**

# 11. Concord-specific material requiring abstraction

Formal extraction must genericise, but preserve provenance for:

- KCS;
- STRA;
- CBER;
- Civilisation Clock / CRSTL;
- FPA/BCA;
- CSHP;
- Historical;
- Continuity;
- Concord-specific constitutional terminology.

These should become generic external interfaces such as:

- dependency/change-propagation owner;
- validation/review owner;
- external-consequence owner;
- temporal/transition-relation owner;
- permission/authority owner;
- specialised handover owner;
- provenance/history owner;
- recovery/continuity owner.

The portable module must not pretend these generic interfaces are supplied by BTA itself.

# 12. Risks entering PMEDG

Main extraction risks:

1. **over-generalisation** — making BTA so abstract that it becomes a generic state-machine description;
2. **owner leakage** — silently importing Concord owner semantics into the portable module;
3. **schema inflation** — treating every possible interface as mandatory;
4. **authority laundering** — allowing transition necessity to create authority;
5. **completion laundering** — treating one owner-system completion as integrated completion;
6. **ESCP overreach** — treating missing dimensions as proof of failure rather than bounded uncertainty;
7. **bureaucratic overuse** — applying BTA below its materiality gate.

All are already represented in the development record and can become explicit portable failure criteria.

# 13. PMEDG stage decision

**DECISION: ENTER FORMAL PMEDG AS A LEVEL B EXTRACTABLE ARCHITECTURE.**

BTA should no longer be treated only as an unconstrained Active Development sketch.

It is not yet a graduated portable module.

The next formal artifact required by PMEDG is:

> **BTA — Source Resolution and Extraction Audit 001**

That audit should use the existing BTA development record as source evidence, identify the full source set, extract the generic kernel, classify each Concord-specific dependency as removable/generic interface/already-owned/unresolved, and define the standalone portable-module boundary.

# 14. Candidacy conclusion

> **BTA has crossed the threshold from architecture discovery into defensible portable-module extraction candidacy.**

Current evidence does not justify skipping PMEDG. It justifies entering it.

**CANDIDACY RESULT: ACCEPT — LEVEL B.**
