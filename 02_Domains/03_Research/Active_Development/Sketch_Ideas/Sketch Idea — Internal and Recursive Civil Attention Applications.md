# Sketch Idea — Internal and Recursive Civil Attention Applications

**Origin:** Civil Attention portable-module graduation discussion
**Date:** 25 September 2026
**Status:** SKETCH / UNTESTED / NON-CANONICAL

## Observation

The graduated Civil Attention core is participant-relative rather than necessarily public-relative. A participant could potentially be a citizen, worker, manager, department, contractor, AI agent, operator, auditor or another legitimate internal function.

This suggests that the same general attention architecture may be useful internally within organisations and operational systems, not only for public-facing civil reporting.

## Candidate Transfer Principle

> **Civil Attention Is Participant-Relative, Not Public-Relative.**

Possible recursive use:

**Participant/Worker/Function → Common Internal Attention → Issue → Appropriate Owner(s) → Action/Processing → Mandatory Return → Resolution/Feedback**

A domain may therefore be able to use the same graduated core at a smaller organisational scale rather than inventing a separate reporting architecture.

> **The Same Attention Architecture May Be Recursively Instantiated at Different Organisational Scales.**

## Candidate Applications

Potential future tests include:
- worker-to-manager issue reporting;
- employee safety or process observations;
- department-to-department problem reporting;
- manager escalation;
- internal suggestions and petitions;
- contractor/operator reporting;
- AI- or system-generated observations requiring human/institutional attention;
- operational exception reporting;
- workflow initiation from an observed problem;
- cross-functional issue tracking.

## Boundary With Workflow Systems

Civil Attention should not automatically become a universal project-management or workflow-execution system.

Candidate separation:

**Observation / Attention Trigger → Civil Attention Issue → Legitimate Work Requirement → Workflow/Task System → Execution → Status/Disposition Return → Civil Attention Resolution**

Civil Attention identifies, preserves, routes and tracks the need for attention. A workflow/task system may execute the resulting work.

## Core-Drift Constraint

This observation does **not** amend Civil Attention Module v1.0.

Internal/recursive use should first be developed as a specific extension or Domain Companion and transfer-tested.

If testing reveals a genuinely universal improvement, it may enter the established controlled back-propagation/core-revision process.

> **Internal Application ≠ Permission to Rewrite the Core**

## Development Question

Can the graduated Civil Attention core be recursively instantiated for internal organisational reporting and operational exception handling while preserving the same authority, provenance, routing, return and anti-drift invariants?

## Current Decision

Preserve as a future extension/refinement candidate. Do not claim this application as validated by the existing BTT-001/BTT-002 record.
