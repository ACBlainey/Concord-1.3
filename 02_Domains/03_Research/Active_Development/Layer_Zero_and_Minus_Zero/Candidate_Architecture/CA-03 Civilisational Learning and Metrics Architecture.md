## 1. Architecture Statement

> **A civilisation should be able to convert actual outcomes into corrigible structural knowledge while preserving provenance, uncertainty, minority and outlier visibility, and avoiding unnecessary retention or propagation of participant identity.**

## 2. Origin and Provenance

This architecture consolidates:

- Case-Learning and Structural Knowledge System;
- Automatic Anonymised Metrics Extraction System;
- Metrics Reliability, Correction and Meta-Metrics System.

It interfaces with:

- Reality Trees;
- Citizen Data Ownership, Access and Contestability;
- CA-04 Purpose-Limited Participant Information;
- CA-05 Predictive System-Steering and Resource Allocation.

## 3. Civilisational Problem Addressed

A civilisation can fail to learn because:

- useful case knowledge remains trapped locally;
- identity is retained unnecessarily;
- Metrics hide uncertainty;
- corrections do not propagate;
- averages erase minority harm;
- definitions change invisibly.

This architecture seeks to make collective learning possible without making every participant a permanent object of observation.

## 4. Intended Scope

Applicable to:

- civil Metrics;
- programme evaluation;
- public services;
- resource demand;
- health and safety learning;
- infrastructure performance;
- governance evaluation;
- multisubstrate civil outcomes.

## 5. Explicit Non-Scope

This architecture does not:

- establish individual guilt or authority;
- imply that aggregate pattern proves individual condition;
- guarantee causation from correlation;
- require public exposure of protected information;
- treat every metric as objective truth.

## 6. Principal Components

### 6.1 Case-Learning and Structural Knowledge
Extracts generalisable structural learning from actual cases.

### 6.2 Automatic Anonymised Metrics Extraction
Transforms operational observations into appropriately minimised civil Metrics.

### 6.3 Metrics Reliability and Correction
Preserves provenance, uncertainty, correction history and definition changes.

### 6.4 Meta-Metrics
Measures the quality, reliability and behaviour of the Metrics themselves.

## 9. Authority Flow

CA-03 produces knowledge.

It should not automatically generate individual authority.

Aggregate risk, neighbourhood patterns or demographic trends should not be treated as individual proof.

## 10. Required Boundaries

### 10.1 Outlier Visibility
Outcomes should not be reduced exclusively to averages.

### 10.2 Distributional Metrics
Where relevant, systems should preserve distributions, severity and minority impact.

### 10.3 Correction Propagation
Material corrections should propagate to downstream systems where earlier values materially influenced models or decisions.

### 10.4 Definition Provenance
Changes in what a Metric means should remain visible.

### 10.5 Substrate Assumptions
Metrics should identify human, AI or other substrate assumptions where relevant.

### 10.6 Epistemic Weighting
Observation, inference, hypothesis and provisional data should not silently collapse into one confidence category.

## 11. Failure Behaviour

If CA-05 fails:

- CA-03 can continue learning.

If CA-02 fails:

- CA-03 can continue analysing actual outcomes.

If CA-04 fails:

- downstream identifiable information movement should restrict rather than become open.

If Metrics become unreliable:

- automated or high-consequence downstream steering should reduce accordingly.

## 12. Anti-Capture Safeguards

Key risks:

- metric gaming;
- institutional self-evaluation;
- Goodhart effects;
- definitional manipulation;
- minority invisibility.

Safeguards:

- meta-Metrics;
- provenance;
- contestability;
- outlier analysis;
- independent review;
- definition history.

## 13. Cross-Substrate Considerations

Metrics must not silently define human-normal behaviour as universal wellbeing.

Future development should examine:

- AI continuity;
- compute health;
- communication norms;
- collective identities;
- hybrid data.

## 14. Adversarial Findings

The architecture survived first-stage failure testing.

Required additions:

- distributional Metrics;
- outlier visibility;
- correction propagation;
- explicit substrate assumptions;
- epistemic weighting.

## 15. Unresolved Questions

- How much provenance is sufficient?
- How should rare-case re-identification risk be handled?
- How should causal claims be distinguished from correlation?
- How are public Metrics balanced against privacy?
- How should information overload be prioritised?
