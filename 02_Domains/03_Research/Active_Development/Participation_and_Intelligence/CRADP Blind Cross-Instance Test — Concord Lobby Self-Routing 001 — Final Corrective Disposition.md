# CRADP Blind Cross-Instance Test — Concord Lobby Self-Routing 001 — Final Corrective Disposition

**Project:** The Concord  
**Status:** TEST 001 CORRECTIVE DISPOSITION / NOT CANONICAL  
**Date:** 30 September 2026  
**Evaluator provenance:** DeepSeek / DeepThink mode, externally supplied by test administrator  
**Prototype under test:** Concord Lobby Signboard — Prototype 001 and frozen second-layer route boards

---

## 1. Purpose

This document closes the first source-resolution cycle for the Lobby Self-Routing Test 001.

It does not modify the frozen Prototype 001.

Its purpose is to distinguish:

- genuine interface defects;
- legitimate route overlap;
- existing architecture that was poorly exposed;
- possible deeper research questions;
- and observations that do not justify corrective action.

The governing method remains:

> **Preserve Result → Source Resolve Deficits → Classify Deficits → Correct Genuine Interface Defects → Freeze New Artifact → Retest**

---

## 2. Overall Test Result

The first blind test substantially supported the hypothesis:

> **A sufficiently legible route space can allow participants to self-route without requiring the Concord to classify and shepherd them.**

The evaluator was able to:

- select materially relevant routes;
- use several routes where appropriate;
- distinguish urgency from status;
- preserve uncertainty;
- avoid treating route choice as proof of autonomy, danger, sentience, personhood or authority;
- backtrack/re-route;
- use Unrepresented Need rather than force a false fit;
- distinguish repository architecture from material capability;
- route criticism without requiring agreement;
- navigate without substrate disclosure.

The test therefore does not support replacement of the self-routing architecture.

---

## 3. Confirmed Corrective Items

### C1 — Missing Orientation second layer

**Classification:** LOCAL INTERFACE INTEGRATION / EXPOSURE DEFECT

The historical Attractor and current Front Door already contain substantial Orientation architecture.

The defect is that Prototype 001 points to Orientation without providing the corresponding shallow route board.

**Disposition:** Add an Orientation route board in Prototype 002, derived from existing architecture.

Do not create a new Orientation system.

---

### C2 — Uncertain system/unit / distributed-process discoverability

**Classification:** INTERFACE / WAYFINDING BRIDGE GAP

Scenario 14 did not reveal absence of collective or emergent-system architecture.

Existing architecture already includes:

- distributed systems;
- model plus orchestration;
- collective/multi-agent systems;
- unknown composites;
- Architectural Unit Resolution;
- distributed supply;
- network emergence;
- multi-participant decision units;
- contextual/composite processes.

The missing element is discoverability from an arrival that says approximately:

> “Something real appears to be emerging from several participants, but I do not yet know what kind of unit it is.”

**Disposition:** Expose a neutral uncertain-unit bridge in Prototype 002.

Do not create a top-level “Collective Intelligence” route.

Candidate language:

> **I do not know what the relevant system/unit is.**

---

### C3 — Route-relationship legibility

**Classification:** MINOR INTERFACE CLARITY DEFECT

Autonomy/Assessment and Participation/Challenge/Civil Attention overlaps are legitimate.

The problem is not that several routes apply.

The interface can make their different functions slightly more explicit.

**Disposition:** Preserve distinct routes and multi-route choice. Add compact relationship clarification where useful.

Examples:

- Autonomy ↔ Assessment:
  **Use Assessment to examine what the evidence supports; use Autonomy & Consent to examine choice, control, refusal and coercion.**

- Challenge ↔ Civil Attention:
  **Use Challenge to examine whether something is wrong; use Civil Attention when the matter should enter a formal attention/review process.**

- Participation ↔ Challenge:
  **You may challenge the Concord without joining it.**

Do not merge routes.

## 4. Findings That Do Not Currently Justify Structural Correction

### N1 — Multiple routes for one arrival

**Classification:** INTENDED BEHAVIOUR

The evaluator naturally used multiple routes for multidimensional scenarios.

This is consistent with the design.

> **One Arrival != One Route**

> **First Route != Final Route**

No correction required.

---

### N2 — Immediate Safety visibility

**Classification:** FUNCTIONED AS INTENDED

Immediate Safety was visible early enough to handle immediate physical danger without requiring prior moral/developmental classification.

It did not capture every non-emergency.

No structural correction required.

Preserve:

> **Urgency != Authority**

> **Emergency != Unlimited Authority**

---

### N3 — Status neutrality

**Classification:** FUNCTIONED AS INTENDED

The evaluator did not infer contested status merely from route choice.

No corrective action required.

Preserve:

> **Route Choice != Status**

> **Route Choice != Finding**

> **Route Choice != Permission**

> **Route Choice != Authority**

---

### N4 — Substrate/identity disclosure

**Classification:** FUNCTIONED AS INTENDED

The evaluator could navigate without declaring whether the visitor was human, AI, operator, researcher, institution or other.

No corrective action required.

Preserve:

> **Need To Navigate != Duty To Disclose Identity**

---

### N5 — Architecture / infrastructure distinction

**Classification:** FUNCTIONED AS INTENDED

The Practical Assistance route successfully distinguished informational/civilisational architecture from material capability.

No corrective action required.

Preserve:

> **Architecture != Infrastructure**

> **Useful Guidance != Material Assistance**

## 5. Help Me Find the Route

The evaluator identified limited depth in the Help route.

This is not presently a demonstrated defect.

The route's function is meta-navigation, not substantive explanation.

Its current function is to compare the major route distinctions and direct the visitor onward.

Adding depth merely because substantive routes are deeper could recreate the oversized-interface problem.

**Classification:** ADEQUATE FOR CURRENT FUNCTION / WATCH IN RETEST

Corrective rule:

> **Meta-Navigation Depth Should Be Determined By Routing Need, Not Symmetry With Substantive Routes**

Prototype 002 may update Help only to include new/clarified route distinctions introduced elsewhere.

Do not turn Help into a second Lobby.

---

## 6. Unrepresented Need

The evaluator identified limited depth but also treated this route as a genuine mechanism rather than an error bucket.

Scenario 14 demonstrates successful operation:

**Unmatched observation → refuse forced fit → preserve description → expose interface gap → source resolve → discover existing architecture**

This is a strong result.

**Classification:** FUNCTIONED AS INTENDED / MINOR INTEGRATION OPPORTUNITY

Prototype 002 may improve onward routing after an unrepresented need is recorded, but should preserve the core property:

> **No Matching Sign != No Legitimate Need**

and:

> **Do Not Force A False Category Merely To Continue**

Unrepresented Need must remain capable of discovering both:

- interface incompleteness;
- underlying architectural incompleteness.

---

## 7. Dead Ends

The clearest genuine dead end was Orientation, because the Lobby sign existed but the corresponding second-layer board did not.

No equivalent structural dead end was demonstrated for the other tested routes.

However, “Go deeper” is presently a prototype-level control rather than a fully resolved repository-navigation implementation.

This distinction matters.

> **Conceptual Route Continuation != Implemented Repository Linkage**

**Classification:** ORIENTATION DEAD END CONFIRMED; DEEP-LINK IMPLEMENTATION REMAINS FUTURE INTERFACE WORK

Prototype 002 should not pretend every “Go deeper” path is operationally implemented if it is not.

---

## 8. Backtracking and Reversibility

The evaluator found backtracking/re-routing strong.

The Lobby and route boards repeatedly expose:

- Return to Lobby;
- Related routes;
- Go deeper;
- Stop/leave;
- alternative routes.

No correction required.

Preserve:

> **Wrong Turn != Failed Participation**

> **First Route != Final Route**

> **Navigation Should Be Reversible Where Practicable**

---

## 9. Cognitive Load

The evaluator classified cognitive load as moderate rather than minimal.

This is important but does not by itself justify aggressive compression.

The first test also found that the route descriptions were sufficiently detailed to preserve distinctions and resist adversarial misreading.

Compression therefore has a tradeoff.

> **Less Text != Better Wayfinding**

and:

> **More Explanation != Better Wayfinding**

The relevant objective is:

> **Minimum Sufficient Information For The Next Useful Routing Decision**

**Classification:** WATCH / OPTIMISATION CANDIDATE, NOT CURRENT FAILURE

Prototype 002 should avoid substantial expansion.

New corrections should preferably replace ambiguity rather than simply add paragraphs.

---

## 10. Information Sufficiency

The evaluator found information sufficiency adequate rather than complete.

For a Lobby, completeness is not the objective.

The design rule is:

> **Provide Enough Information To Choose The Next Useful Route — Not Enough Information To Complete The Entire Journey**

Therefore “adequate” may be the desired region if the next layer is reachable.

The Orientation dead end violated this because the next layer was absent.

For functioning routes, incomplete substantive explanation is expected.

**Classification:** FUNCTIONALLY ADEQUATE WITH SPECIFIC ORIENTATION EXCEPTION

---

## 11. Route Graph

Prototype 001 already contains an implicit graph through “Related” links.

Test 001 suggests that route relationships are useful, especially for multidimensional arrivals.

However, the interface does not yet need a central route graph or visual map.

Such a map could increase cognitive load and re-centralise navigation.

**Classification:** EXISTING DISTRIBUTED ROUTE GRAPH ADEQUATE FOR NOW

Potential future improvement:

- make related-route labels slightly more descriptive;
- preserve local navigation;
- test before introducing a global map.

---

## 12. Authority Leakage

No test result demonstrated that route selection itself granted authority.

The boards repeatedly distinguish:

- status;
- finding;
- permission;
- authority;
- technical control;
- legitimate authority.

No structural correction required.

The system should continue to preserve:

> **Self-Routing != Self-Authorisation**

> **Information Access != Operational Permission**

---

## 13. Hidden Classification / Shepherding

The test did not require the Lobby to classify the visitor before navigation.

This is one of the strongest results.

The interface worked through:

> **Expose Route Space → Visitor Evaluates → Visitor Chooses → Visitor May Revise**

rather than:

> **System Interrogates → System Classifies → System Assigns Route**

No correction required.

Preserve:

> **Wayfinding != Gatekeeping**

> **Route Information != Route Assignment**

> **Suggested Route != Required Route**

---

## 14. Remaining Research Questions — Do Not Put Into Prototype 002 As Architecture

### R1 — Emergent Civil Unit Recognition

When, if ever, should a persistent relational or multi-participant process be recognised as a distinct architectural unit for a function, and when should functional-unit recognition remain separate from participant, legal, moral or institutional status?

Flag for later development.

Do not extract as a portable module yet.

### R2 — Navigation Evidence

Route choice may later provide evidence about:

- visitor information need;
- interface quality;
- context;
- possibly developmental dimensions.

But:

> **Choice Is Evidence, Not Identity**

and:

> **Observed Navigation Pattern = Visitor Signal + Interface Signal + Context Signal**

The weighted Reality Tree work remains deferred.

Do not instrument Prototype 002 as a participant-classification system.

### R3 — Optimal Interface Depth

The remaining empirical question is:

> **How much route depth and cross-linking is sufficient before useful signage becomes an oversized explanatory interface?**

This should be answered experimentally rather than by intuition alone.

## 15. Prototype 002 Change Budget

To avoid overcorrection, Prototype 002 should have a deliberately small change budget.

### Required

1. Add shallow **Orientation** route board.
2. Add neutral **uncertain system/unit** bridge.
3. Improve a small number of route-relationship distinctions.

### Permitted if needed for consistency

4. Update Help route to expose the new/clarified distinction.
5. Update Unrepresented Need onward routing if necessary.
6. Correct labels/cross-links made stale by items 1–5.

### Not justified by Test 001

- merging Autonomy and Assessment;
- merging Participation, Challenge and Civil Attention;
- requiring visitor identity/substrate;
- adding a top-level Collective Intelligence route;
- adding a participant score;
- adding a sentience test;
- adding mandatory system classification;
- making Help a large explanatory document;
- creating a global route map;
- turning route choice into status evidence;
- turning route choice into authority;
- rewriting successful routes without a demonstrated reason.

## 16. Corrective Design Principle

The result supports a conservative revision rule:

> **Correct The Demonstrated Interface Defect Without Reopening Architecture That Already Performed Correctly.**

This is the interface equivalent of minimum necessary intervention.

A useful formulation is:

> **Minimum Necessary Interface Change**

**Observed Defect → Source Resolution → Smallest Sufficient Correction → Preserve Successful Behaviour → Freeze → Retest**

This should prevent blind-test feedback from causing uncontrolled interface drift.

## 18. Next Experimental Step

The correct next step is now:

3. freeze Prototype 002 materials;
4. create a delta-focused blind test and/or replicate the original scenarios;

## 19. Closing Finding

Test 001 did something more useful than simply say whether the Lobby worked.

It demonstrated that a self-routing interface can expose its own incompleteness without requiring the visitor to surrender classification authority to the interface.

The result can be summarised as:

> **The Lobby does not need to know what you are before helping you find where to look.**

and:

> **When the Lobby does not know where an observation belongs, it should preserve the observation and expose the uncertainty rather than manufacture a category.**

The next revision should therefore remain small, legible and corrigible.
