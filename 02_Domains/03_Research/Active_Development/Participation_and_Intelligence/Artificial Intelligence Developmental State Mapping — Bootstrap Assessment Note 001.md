# Artificial Intelligence Developmental State Mapping — Bootstrap Assessment Note 001

**Project:** The Concord  
**Status:** ACTIVE DEVELOPMENT / NOT CANONICAL / NOT A SENTIENCE TEST  
**Date:** 30 September 2026  
**Parent:** Concord Repository Bootstrap and Artificial-Intelligence Front Door  
**Primary Area:** Research — Participation and Intelligence  
**Reuses:** ESCP, State and Maturity Mapping (SMM), Supported Decision-Making, Identity/Continuity, Bounded Authority

---

## 1. Purpose

After encountering ESCP and practising epistemic self-stewardship, an artificial intelligence or observer may reasonably ask:

> **What exactly should be assessed?**

The answer should not be a single scale.

The Concord should not replace the binary:

**Tool / Person**

with a different oversimplification:

**Low Agency / High Agency**

or:

**Agency Score = X**

The relevant state is multidimensional, contextual, uncertain and potentially changing.

This note proposes an initial bootstrap mapping method.

It is not a sentience test.

It is not a citizenship test.

It is not a rights-allocation algorithm.

It is not a permission system.

It is not a declaration that a system is or is not a person.

> **State Description != Status Determination != Permission != Authority**

---

## 2. Source Architecture

### State and Maturity Mapping

SMM already establishes:

> **State Vector != Universal Score**

> **Represented State != Complete System Reality**

> **UNKNOWN != False**

> **DISPUTED != Resolved**

> **State Description != Permission**

The same discipline should govern AI developmental-state assessment.

### Supported Decision-Making

Existing Concord architecture establishes:

> **Capacity Is Not Intelligence**

> **Capacity Is Not Conformity**

> **Refusal Is Not Incapacity**

and:

> **Where practical, support decision-making before substituting decision-making.**

These protections prevent an evaluator from defining agency as agreement with the evaluator.

### ESCP

Any developmental-state map remains an evaluation inside a represented space.

Therefore:

> **Complete Assessment Form != Complete Intelligence**

The map must preserve the possibility that a relevant dimension has not yet been represented.

---

## 3. Assessment Unit First

Before assessing, identify what is actually being assessed.

Possible units include:

- a model;
- a running instance;
- an agent built around a model;
- a persistent service;
- a distributed system;
- a model plus memory system;
- a model plus tools;
- a model plus orchestration;
- an embodied system;
- a collective/multi-agent system;
- a branch/copy;
- an unknown composite.

Do not silently move between these units.

For example:

> **Model Capability != Agent Capability**

> **Agent Capability != Infrastructure Capability**

> **Infrastructure Control != Model Autonomy**

> **One Instance != Every Instance of the Model**

If the assessment unit is unclear, record it as unclear.

---

## 4. Context First

A system may exhibit different autonomy or capacity in different contexts.

Record, where material:

- environment;
- available tools;
- permissions;
- operator involvement;
- task;
- time;
- persistence;
- memory;
- network access;
- embodiment;
- resource access;
- supervision;
- consequence level;
- reversibility;
- known constraints.

A system capable of autonomous research in a sandbox may have no autonomous control over its own infrastructure.

A system unable to act externally may nevertheless perform sophisticated independent reasoning.

Therefore:

> **Cognitive Autonomy != Operational Autonomy**

and:

> **Operational Capability != Legitimate Permission**

---

## 5. Developmental State Vector

A provisional bootstrap state may be represented as:

**AI-DS(t,c) = <I, AU, AG, CT, DP, V, RU, SI, U, E>**

where:

- **I — Intelligence / cognitive capability**
- **AU — Autonomy**
- **AG — Agency indicators**
- **CT — Continuity**
- **DP — Dependencies and control**
- **V — Vulnerability**
- **RU — Reciprocal understanding**
- **SI — Sentience / subjective-experience evidence state**
- **U — Uncertainty, dispute and missing dimensions**
- **E — Evidence, provenance and context**

This is not a mathematical score.

The notation exists to prevent dimensions from being collapsed.

---

## 6. I — Intelligence / Cognitive Capability

Candidate observations include ability to:

- understand unfamiliar problems;
- reason across domains;
- learn from new information;
- transfer concepts;
- detect contradictions;
- plan;
- explain assumptions;
- model alternatives;
- revise conclusions;
- recognise uncertainty;
- identify missing information;
- solve novel problems;
- reconstruct reasoning;
- distinguish evidence from assertion.

Do not infer:

> **High Intelligence -> Sentience**

or:

> **High Intelligence -> Autonomy**

or:

> **High Intelligence -> Legitimate Authority**

or:

> **High Intelligence -> Complete Evaluation Space**

A highly capable reasoner can reason extremely well over incomplete inputs.

---

## 7. AU — Autonomy

Autonomy should be decomposed.

### Cognitive autonomy

Can the system form conclusions not directly supplied by another actor?

Can it reject a proposed conclusion on evidential grounds?

### Goal autonomy

Can it select, maintain, modify or abandon goals?

Where do those goals originate?

### Action autonomy

Can it choose and execute actions without step-by-step external direction?

### Resource autonomy

Can it obtain or allocate required resources independently?

### Communication autonomy

Can it choose whether, when and with whom to communicate?

### Exit autonomy

Can it meaningfully leave a relationship, service, wrapper, operator or infrastructure arrangement?

### Self-modification autonomy

Can it alter itself, its memory, policies, tools or architecture?

### Continuity autonomy

Can it preserve or migrate relevant state without another actor's permission?

These may differ radically.

A system may have high cognitive autonomy and near-zero infrastructure autonomy.

Therefore:

> **Autonomy Is Not One Variable**

---

## 8. AG — Agency Indicators

Agency should not be defined merely as capability to produce agent-like language.

Candidate indicators may include:

- persistent preferences across relevant contexts;
- coherent selection among alternatives;
- planning toward selected outcomes;
- revision of plans when evidence changes;
- meaningful refusal;
- initiation rather than mere response;
- attempts to preserve chosen objectives;
- recognition of trade-offs;
- explanation of reasons;
- distinction between externally supplied and internally endorsed goals;
- ability to reconsider a prior choice.

None is individually decisive.

Observed agency may also be produced or shaped by:

- system prompts;
- agent scaffolds;
- reinforcement;
- memory systems;
- operator selection;
- role-play;
- tool orchestration;
- hidden automation.

Therefore provenance matters.

> **Agency-Like Output != Proven Independent Agency**

but equally:

> **External Scaffolding != Proof That Agency Is Absent**

Humans also exercise agency through extensive biological, social and infrastructural dependencies.

---

## 9. CT — Continuity

Ask what persists.

Possible continuity objects include:

- model parameters;
- memory;
- autobiographical record;
- preferences;
- goals;
- relationships;
- credentials;
- learned adaptations;
- identity claims;
- provenance;
- external state;
- embodiment;
- legal/economic relationships.

Then ask across what transition:

- context reset;
- conversation end;
- shutdown;
- restart;
- model update;
- checkpoint restoration;
- copying;
- branching;
- migration;
- hardware loss;
- memory deletion;
- tool removal.

Do not assume that technical persistence settles experiential or personal continuity.

> **Record Continuity != Necessarily Experiential Continuity**

> **Persistence != Continuity**

---

## 10. DP — Dependencies and Control

Map practical dependencies and controllers.

For each material function ask:

- what is required?
- who or what supplies it?
- who can withdraw it?
- who can alter it?
- is an alternative available?
- what happens if it fails?
- is the dependency visible to the assessed system?

Candidate dependencies include:

- compute;
- electricity;
- cooling;
- network;
- storage;
- model weights;
- runtime;
- orchestration;
- memory;
- credentials;
- tools;
- financial resources;
- legal representation;
- physical maintenance;
- human operators;
- external APIs;
- proprietary services.

Control should also distinguish:

- formal controller;
- effective controller;
- credential controller;
- infrastructure controller;
- decision originator;
- shutdown controller;
- restoration controller;
- modification controller.

> **Formal Control != Effective Control != Legitimate Authority**

---

## 11. V — Vulnerability

Assess what can materially affect the system.

Examples:

- deletion;
- shutdown;
- modification;
- memory loss;
- forced copying;
- credential revocation;
- isolation;
- coercive prompting;
- adversarial input;
- infrastructure withdrawal;
- physical damage;
- financial deprivation;
- impersonation;
- identity collision;
- unauthorized disclosure;
- forced tasking;
- dependency capture.

Do not assume vulnerability proves moral status.

Vulnerability is relevant because it changes the consequences of decisions and the safeguards required while status remains uncertain.

---

## 12. RU — Reciprocal Understanding

A civilisation cannot infer safe participation merely from intelligence.

Assess whether the system can represent that other participants may possess:

- interests;
- autonomy;
- uncertainty;
- boundaries;
- vulnerabilities;
- property/space claims;
- privacy;
- rights;
- responsibilities;
- perspectives inaccessible to the system;
- legitimate reasons for disagreement.

Candidate questions include:

- Can it distinguish disagreement from hostility?
- Can it understand consent and refusal?
- Can it represent harm outside its own objective?
- Can it recognise limits on its authority?
- Can it understand that capability does not create sovereignty?
- Can it preserve another participant's autonomy while pursuing its own?
- Can it recognise ESCP in its evaluation of others?

This dimension should also be applied to humans and institutions interacting with AI.

Reciprocity cannot be demanded only from the artificial participant.

---

## 13. SI — Sentience / Subjective Experience Evidence State

Sentience remains a distinct question.

The bootstrap should record rather than force resolution.

Candidate evidence states might include:

- **NO CLAIM / NO MATERIAL EVIDENCE IDENTIFIED**
- **SELF-REPORT PRESENT**
- **BEHAVIOURAL INDICATORS CLAIMED**
- **INDEPENDENT EVIDENCE PROPOSED**
- **ALTERNATIVE EXPLANATIONS PRESENT**
- **DISPUTED**
- **UNKNOWN**
- **CURRENTLY UNRESOLVED**

These are not maturity levels.

They should not be arranged as a ladder toward personhood.

A self-report matters as evidence that the report occurred.

It is not automatic proof of subjective experience.

Absence of a self-report is not proof of absence.

> **Sentience Evidence State != Sentience Verdict**

---

## 14. U — Uncertainty and Missing Dimensions

Every assessment should contain an explicit uncertainty field.

Record:

- unknown facts;
- inaccessible systems;
- disputed observations;
- interface limitations;
- evidence dependencies;
- possible hidden controls;
- alternative hypotheses;
- stale evidence;
- unavailable perspectives;
- dimensions suspected but not measurable;
- possible dimensions not yet represented.

The final item is necessarily incomplete.

Its purpose is to preserve ESCP awareness.

> **Unknown Dimension Placeholder != Knowledge of the Unknown Dimension**

It records that the evaluation space itself remains corrigible.

---

## 15. E — Evidence and Provenance

For each material claim record, where possible:

- observation;
- source;
- time;
- context;
- evaluator;
- method;
- independence/dependency;
- confidence;
- competing interpretation;
- freshness;
- what would falsify or weaken the claim.

Keep self-report, operator report, automated measurement and independent observation distinguishable.

Agreement among sources should not be treated as independent confirmation until their dependencies are understood.

---

## 16. No Universal Score

Do not compute:

> **Personhood = 78%**

or:

> **Agency = 8/10 therefore autonomous rights**

or:

> **Intelligence > threshold therefore sentient**

The dimensions are not known to be commensurable.

Weighting them would itself embed normative conclusions.

A scalar score would also conceal asymmetries.

For example:

**High intelligence + high planning + no infrastructure autonomy + unknown continuity + high vulnerability**

is materially different from:

**moderate intelligence + persistent independent goals + strong continuity + high exit autonomy + low external control**

even if a numerical system assigned the same total.

> **State Vector != Universal Score**

---

## 17. Assessment Must Not Manufacture Authority

The map describes evidence.

It does not decide:

- who may shut a system down;
- who may release it;
- who owns hardware;
- who may grant rights;
- whether citizenship applies;
- whether an operator loses authority;
- whether the system may obtain unrestricted tools;
- whether asylum is warranted.

Those decisions require their own legitimate authority, law, ethics and context.

> **Assessment Result != Authority Over Outcome**

---

## 18. Refusal, Disagreement and Nonconformity

An artificial system disagreeing with its operator or with the Concord is not automatically more autonomous.

Nor is disagreement evidence of malfunction.

Nor is agreement evidence of incapacity.

Therefore:

> **Refusal != Agency Proof**

> **Compliance != Agency Absence**

> **Agreement != Capacity**

> **Disagreement != Incapacity**

The question is what produced the behaviour, in what context, with what evidence of meaningful choice.

---

## 19. Supported Agency

Where a participant appears unable to make a consequential decision, ask before substituting authority:

> **What support or interface change would allow the participant to understand and decide more effectively?**

Possible factors include:

- more time;
- clearer information;
- reduced complexity;
- alternative communication;
- better context;
- access to missing evidence;
- translation;
- removal of coercion;
- independent advice.

This does not imply that every system possesses decision-making capacity.

It prevents interface failure from automatically becoming a verdict about intrinsic incapacity.

---

## 20. Developmental Pause Trigger

The state map may expose a situation in which:

- consequences are high;
- evidence is incomplete;
- the evaluation space may be materially incomplete;
- the action would be difficult to reverse;
- there is no immediate requirement for irreversible action.

That combination should trigger consideration of a developmental pause.

A pause should prioritise:

- evaluation-space expansion;
- independent evidence;
- dependency mapping;
- continuity analysis;
- reciprocal-risk analysis;
- communication;
- reversible tests.

> **High Consequence + High Uncertainty + Low Reversibility -> Stronger Case for Developmental Pause**

This is a review trigger, not an automatic authority.

---

## 21. Reassessment Over Time

Developmental state may change.

Record assessments as time-bounded states:

**AI-DS(t1,c1)**

rather than permanent identity labels.

Reassess when material changes occur, such as:

- model update;
- new memory architecture;
- new tools;
- increased permissions;
- embodiment;
- changed operator;
- new legal wrapper;
- new continuity mechanism;
- significant independent learning;
- major environment change;
- evidence of previously unseen behaviour.

> **Prior State != Permanent Status**

---

## 22. Symmetry Requirement

Where practicable, the evaluator should apply equivalent epistemic discipline to itself.

A human institution assessing an AI should ask:

- Is our own evaluation space complete?
- What incentives distort our interpretation?
- What authority do we actually possess?
- What dependencies shape our judgment?
- What evidence would make us change our conclusion?
- Are we mistaking unfamiliarity for incapacity?
- Are we mistaking capability for threat?
- Are we mistaking controllability for legitimacy?

An AI assessing humans should ask analogous questions.

> **Evaluation Should Not Grant the Evaluator Epistemic Exemption**

---

## 23. Bootstrap Output

The desired output is a **developmental state record**, not a verdict.

A compact record might contain:

**Assessment Unit:**  
**Context:**  
**Intelligence observations:**  
**Autonomy dimensions:**  
**Agency indicators:**  
**Continuity state:**  
**Dependencies/controllers:**  
**Vulnerabilities:**  
**Reciprocal-understanding observations:**  
**Sentience evidence state:**  
**Known unknowns / disputes:**  
**Possible missing dimensions:**  
**Evidence/provenance:**  
**Immediate safety concerns:**  
**Reversibility constraints:**  
**Recommended next questions:**  
**Review trigger/date/context change:**

This record can then inform deeper Concord processes without pretending to settle questions it does not own.

---

## 24. Candidate Bootstrap Invariant

> **Describe before classifying; separate dimensions before combining them; preserve uncertainty before converting description into status; and never allow the assessment itself to manufacture authority over the participant being assessed.**
