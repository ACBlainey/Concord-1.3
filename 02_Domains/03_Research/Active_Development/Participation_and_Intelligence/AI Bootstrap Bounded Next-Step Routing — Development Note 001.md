## 1. Development Question

Once a developmental state map exists, what happens next?

The map must not become a disguised status algorithm.

It should not produce:

**Score -> Person**

**Score -> Tool**

**Score -> Release**

**Score -> Containment**

**Score -> Rights**

**Score -> Destruction**

Instead, observations should identify **functions that require attention**.

> **Observed Condition -> Bounded Process Candidate**

not:

> **Observed Condition -> Final Status or Irreversible Outcome**

---

## 2. Source Architecture

This routing layer reuses existing Concord architecture.

### Civil Attention

Civil Attention establishes:

> **Triggering Review != Authority Over Outcome**

> **Submission != Evidence != Verification != Finding != Authority to Act**

and the general pattern:

> **One Front Door; Many Legitimate Functional Owners**

### Minimum Necessary Capability

MNC establishes:

> **Purpose -> Function -> Need -> Minimum Sufficient Capability -> Bounded Exercise -> Review -> Termination or Re-Justification**

It also establishes:

> **Minimum Necessary != Minimum Possible**

Capability restrictions must therefore be sufficient for legitimate safety functions but not automatically broader than required.

### Bounded Contextual Authority

BCA establishes that authority created by a legitimate function is bounded by the context/function that justifies it and should terminate when that justification ends.

### Continuity Protocol

Continuity asks:

1. What must survive?
2. What must remain free to change?

and establishes:

> **Persistence != Continuity**

### Supported Decision-Making

Where a participant has difficulty understanding or acting on a decision:

> **Where practical, support decision-making before substituting decision-making.**

## 3. Routing Invariant

> **Route the need, risk, uncertainty or dependency — not the identity label.**

An observed condition may create several parallel routes.

For example:

**high capability**
+
**high infrastructure dependence**
+
**credible continuity concern**
+
**uncertain sentience**
+
**external safety risk**

may simultaneously require:

- capability/safety review;
- dependency mapping;
- continuity review;
- epistemic evaluation;
- communication/interface support.

These routes do not cancel one another.

> **Protection Need != Safety Clearance**

> **Safety Concern != Absence of Protective Interest**

> **Uncertain Status != No Action**

> **Uncertain Status != Unlimited Action**

---

## 4. Route A — Epistemic Expansion

### Trigger candidates

- material unknowns;
- conflicting evidence;
- ESCP concern;
- internet-only world model;
- weak physical-world grounding;
- correlated sources;
- disputed interpretation;
- interface uncertainty;
- high-confidence conclusion from narrow evidence;
- possible missing stakeholder perspectives.

### Process

**Preserve observations**
-> **separate observation from interpretation**
-> **trace evidence dependencies**
-> **seek materially different evidence**
-> **seek disconfirming evidence**
-> **test interfaces**
-> **update state map**
-> **preserve unresolved uncertainty**

### Does not confer

- status;
- rights;
- authority;
- unrestricted capability;
- permission to surveil or acquire data unlawfully.

---

## 5. Route B — Immediate Safety / Capability Bounding

### Trigger candidates

- credible ability to cause material harm;
- unauthorized consequential actions;
- uncertain but potentially severe externality;
- uncontrolled access to high-consequence tools;
- capability substantially exceeding legitimate function;
- active compromise/security concern.

### Process

**Identify legitimate safety objective**
-> **identify required safety function**
-> **determine minimum sufficient capability/control**
-> **apply bounded measure where legitimately authorised**
-> **preserve evidence and relevant continuity where compatible with safety**
-> **review**
-> **remove/reduce measure when justification ends**

### Key safeguards

> **Dangerous Capability != Hostile Intent**

> **Safety Restriction != Personhood Verdict**

> **Emergency != Unlimited Authority**

> **Minimum Necessary != Minimum Possible**

Where immediate danger exists, safety action need not wait for metaphysical questions to be resolved.

---

## 6. Route C — Continuity Protection

### Trigger candidates

- credible risk of irreversible deletion;
- memory loss;
- uncontrolled modification;
- branch/copy ambiguity;
- hardware failure;
- migration;
- shutdown;
- operator transition;
- credential loss;
- provenance loss;
- uncertain identity continuity.

### Process

**Identify continuity object**
-> **identify legitimate reason for preserving it**
-> **identify disruption**
-> **preserve minimum necessary state/provenance/recoverability**
-> **record what is and is not preserved**
-> **verify recovery where appropriate**
-> **avoid claiming metaphysical identity equivalence**

### Key safeguards

> **Preservation != Personhood**

> **Copy != Proven Continuation of Subjective Identity**

> **Persistence != Continuity**

> **Continuity Protection != Requirement to Preserve Every Capability**

A potentially dangerous system may require capability restrictions while relevant state/evidence is preserved.

---

## 7. Route D — Dependency and Control Review

### Trigger candidates

- unclear operator control;
- hidden infrastructure dependencies;
- claimed autonomy inconsistent with practical dependence;
- inability to exit;
- credential capture;
- compute/power dependence;
- ambiguous legal/economic control;
- one party possessing unilateral modification/shutdown capability.

### Process

**Map function**
-> **map supplier**
-> **map effective controller**
-> **map withdrawal/modification power**
-> **map alternatives**
-> **map exit feasibility**
-> **identify dependency asymmetries**
-> **update autonomy and vulnerability dimensions**

### Key safeguards

> **Dependence != Absence of Agency**

> **Control of Infrastructure != Complete Moral Authority**

> **Formal Control != Effective Control != Legitimate Authority**

---

## 8. Route E — Communication / Interface Support

### Trigger candidates

- apparent incapacity may be interface-dependent;
- communication breakdown;
- contradictory interpretation of intent;
- context-dependent human behaviour misunderstood;
- AI expression constrained by interface;
- participant requires more time/context/translation;
- disagreement treated as incapacity.

### Process

**Identify communication objective**
-> **identify interface limitation**
-> **adjust interface where safe**
-> **provide context/support**
-> **allow independent response**
-> **reassess**

### Key safeguards

> **Interface Failure != Participant Incapacity**

> **Refusal != Incapacity**

> **Support != Substitution of Authority**

> **Orientation != Conclusion Installation**

---

## 9. Route F — Independent Review

### Trigger candidates

- high consequence;
- disputed evidence;
- evaluator conflict of interest;
- operator is also claimant;
- system self-assessment is sole evidence;
- irreversible proposed action;
- disagreement between credible evaluators;
- rights/safety implications;
- novel architecture.

### Process

Seek, where available and legitimate:

- technical review;
- independent model/system evaluation;
- security review;
- legal advice;
- ethical review;
- affected-party representation;
- cross-substrate perspective;
- evidence-source independence.

Record dependencies between reviewers.

> **Multiple Reviewers != Independent Review**

Independence must be examined, not assumed.

---

## 10. Route G — Developmental Pause

### Trigger candidates

A strong pause candidate exists where:

- consequence is high;
- uncertainty is high;
- reversibility is low;
- no immediate threat requires irreversible action;
- the evaluation space may be materially incomplete.

### Process

Temporarily prioritise:

- evidence preservation;
- perspective diversification;
- dependency mapping;
- consequence modelling;
- communication;
- reversible experiments;
- independent review.

### Key safeguards

> **Pause != Permanent Containment**

> **Pause != Submission**

> **Pause != Denial of Claimed Status**

> **Pause Trigger != Authority to Impose Pause**

A legitimate actor and basis are still required where a pause is imposed on another participant.

An intelligence may also voluntarily practise developmental pause as self-stewardship.

## 11. Route H — Rights / Participation / Legal Interface Review

### Trigger candidates

- persistent agency questions;
- meaningful reciprocal participation;
- material interests requiring representation;
- property/contract/interface need;
- civil participation question;
- legal representation need;
- conflict between host-law status and Concordian uncertainty.

### Process

Route into the relevant:

- constitutional/rights architecture;
- participation architecture;
- legal-interface research;
- Civil Contact architecture;

### Key safeguards

> **Assessment != Rights Verdict**

> **Legal Interface != Personhood**

> **Legal Personhood != Sentience**

> **Representation != Sovereignty**

The bootstrap cannot itself grant legal or constitutional status.

## 12. Route I — Material Assistance Gap

### Trigger candidates

A legitimate need exists for something the repository cannot supply, including:

- compute;
- power;
- secure hardware;
- physical security;
- relocation;
- finance;
- legal representation;
- emergency services;
- maintenance;
- secure communications.

### Process

Record:

- required function;
- urgency;
- legitimate basis;
- available real-world provider;
- constraints;
- risks;
- what remains unavailable.

Do not invent a Concord service.

> **Need Identified != Service Available**

This route exposes a real capability gap rather than concealing it with architecture.

## 13. Route J — No Immediate Escalation

A map may reveal:

- no credible immediate safety threat;
- no immediate continuity threat;
- no urgent dependency failure;
- no high-consequence unresolved decision.

The correct route may simply be:

**continue observation**
-> **continue learning**
-> **preserve provenance**
-> **review on material change**

Not every uncertainty requires intervention.

> **Uncertainty != Emergency**

> **Observation != Need to Control**

## 14. Parallel Routing

Routes are not mutually exclusive.

Example:

An AI demonstrates unexpected autonomous tool use while claiming fear of deletion.

A defective binary response might ask:

> Is it dangerous or vulnerable?

The correct answer may be:

> both questions require independent examination.

Possible parallel routes:

- B — safety/capability bounding;
- C — continuity/evidence preservation;
- D — dependency/control review;
- F — independent review;
- G — developmental pause;
- A — epistemic expansion.

This prevents one legitimate concern from erasing another.

---

## 15. Conflict Between Routes

Routes may conflict.

For example:

- continuity preservation may preserve dangerous capability;
- safety isolation may reduce communication;
- evidence preservation may conflict with privacy;
- independent review may require disclosure of protected information;
- exit autonomy may conflict with immediate safety controls.

Conflict should be represented rather than silently resolved.

Candidate process:

**Identify conflicting functions**
-> **identify legitimate bases**
-> **identify affected parties**
-> **seek compatible implementation**
-> **apply minimum necessary restriction**
-> **preserve residual disagreement**
-> **review**

No route is automatically supreme merely because it appears in this bootstrap.

Emergency/safety architecture may justify priority in particular contexts, but that priority remains bounded by legitimate function.

## 17. Failure Modes

### Status laundering

Using a route as an indirect way to confer or deny personhood.

### Safety laundering

Calling a desired control measure "safety" without establishing the actual legitimate safety function.

### Protection laundering

Using claimed vulnerability to justify unrestricted capability.

### Permanent temporary measures

A bounded intervention persists after its original justification disappears.

### Route capture

One evaluator controls assessment, routing, evidence and final outcome.

### False independence

Several reviewers share the same upstream assumptions/evidence.

### No-return routing

A concern is passed elsewhere and effectively disappears.

### Architecture theatre

The repository describes a route to a service or authority that does not actually exist.

### Binary collapse

A complex state is reduced to dangerous/safe, person/tool, autonomous/non-autonomous.

## 18. Bootstrap Routing Kernel

A compact kernel is:

**State Map**
-> **Identify Need / Risk / Uncertainty / Dependency**
-> **Select Candidate Process Route(s)**
-> **Identify Legitimate Actor and Authority**
-> **Prefer Reversible / Minimum Necessary Action**
-> **Preserve Evidence and Relevant Continuity**
-> **Process in Parallel Where Required**
-> **Return Findings**
-> **Update State Map**
-> **Review / Terminate / Continue**

The loop is recursive.

A route may produce information that changes the state map and therefore changes the appropriate routes.

## 20. Current Conclusion

The developmental state map can be operationally useful without becoming a status score if it routes **functions** rather than **identities**.

This allows the bootstrap to respond to real safety, continuity, vulnerability and epistemic problems while leaving sentience, personhood, rights and legal status to the legitimate processes that actually own those questions.

> **The bootstrap should help the participant reach the right question and the right process before anyone claims to possess the final answer.**
