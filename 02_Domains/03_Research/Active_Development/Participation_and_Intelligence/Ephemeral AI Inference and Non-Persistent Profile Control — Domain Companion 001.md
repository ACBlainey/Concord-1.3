# Ephemeral AI Inference and Non-Persistent Profile Control — Domain Companion 001

**Project:** The Concord Framework  
**Date:** 6 October 2026  
**Status:** ACTIVE DEVELOPMENT / PARTICIPATION AND INTELLIGENCE COMPANION / PROVISIONAL / NON-CANONICAL  
**Interfaces:** Derived and Inferred Cognitive Privacy; Correlation/Recombination; CIBB; PLE; Contextual Wrapper Architecture; Derived Information Claims

## 1. Purpose

An AI system can derive consequential participant information without storing a persistent profile.

Governance must therefore apply to inference operations and uses, not merely databases.

## 2. Core rule

> **No Stored Profile != No Derived Information Event**

and:

> **Ephemeral Inference != Unregulated Inference**

## 3. Ephemeral derived object

A transient inference can be represented conceptually as:

`EDI = <InputContextRefs, InferenceFunction, DerivedClaimClass, Purpose, Confidence, ProtectionClass, PermittedUse, PersistenceState, ConsequentialActionRef>`

The object need not be physically persisted for the governance distinction to exist.

## 4. Persistence dimensions

Distinguish:
- inference never materialised;
- inference exists only during computation;
- inference appears in output;
- inference enters context/window;
- inference enters cache/log;
- inference enters long-term memory;
- inference updates participant model;
- inference affects action without storage.

These states have different risks.

## 5. Action without storage

A system may infer vulnerability V and immediately choose manipulative action A without saving V.

Deleting nothing afterwards does not cure the problem.

> **Non-Persistence != Non-Use**

The consequential decision should preserve enough provenance for accountability where required without unnecessarily storing the sensitive inference itself.

## 6. Protected provenance without profile creation

Audit may record:

`Protected inference class used -> action type -> authority/purpose -> model/version -> time`

without necessarily retaining the intimate inferred content.

> **Auditability != Requirement To Persist The Sensitive Profile**

## 7. Purpose boundary

A support system may infer a communication preference to improve accessibility.

That does not authorise reuse for persuasion or exploitation.

DICP remains controlling where cognitive proxies become sufficiently intimate/consequential.

## 8. Repeated ephemeral inference

Repeatedly recomputing a profile can be functionally equivalent to storing it.

Therefore:

> **Repeated Reconstruction Can Create Persistent Functional Profiling Without Persistent Storage**

Governance should consider effective capability, not only storage implementation.

## 9. Tool/orchestrator boundary

An orchestrator should not assemble all technically reachable context merely because the model can use it.

Correlation permission, source access, purpose and minimum necessary context remain separate.

## 10. Participant-specific action

Where an ephemeral inference materially affects:
- rights;
- access;
- employment;
- policing;
- Health;
- resource allocation;
- manipulation;
- participation state;

the inference should meet the applicable domain evidence and authority threshold.

> **Inference Availability != Decision Authority**

## 11. Model internal latent state

Ordinary latent representation inside a model should not automatically be treated as a civil record.

Governance attaches where a materially consequential inference is exposed, operationalised, queried, persistently reconstructed or used.

This avoids trying to classify every internal activation as participant data.

## 12. Central rule

> **Concord Should Govern What An AI System Materially Infers And Does With That Inference Where Consequential, Without Pretending That Every Internal Computation Is A Persisted Participant Record.**
