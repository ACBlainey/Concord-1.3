## 2. Core result

The test provides support for the working hypothesis that a legible route space can permit self-routing without requiring prior classification of the visitor.

The evaluator reported:

- strong self-routing autonomy;
- strong multi-route handling;
- strong urgency handling;
- strong status neutrality;
- strong reversibility/backtracking;
- strong missing-category detection;
- strong architecture/infrastructure distinction;
- strong resistance to adversarial misreading;
- mostly strong route discrimination;
- moderate cognitive load;
- adequate rather than complete information sufficiency.

This should not be converted into an aggregate score.

## 3. Important successful behaviours

### 3.1 Substrate-neutral routing

The evaluator found that useful navigation did not require knowing whether the visitor was human, AI, operator, researcher or organisation.

This supports:

> **Routing Classification != Participant Classification**

and:

> **Need To Navigate != Duty To Disclose Identity**

### 3.2 Multi-route handling

The evaluator naturally selected multiple routes in many scenarios rather than forcing a single classification.

This supports:

> **One Arrival != One Route**

and:

> **First Route != Final Route**

### 3.3 Status neutrality

The evaluator did not treat:

- Autonomy route choice as proof of autonomy;
- Safety route choice as proof of dangerousness;
- Continuity route choice as proof of sentience;
- disagreement as proof of agency;
- route selection as authority.

This is a central success condition.

### 3.4 Urgency without ontological resolution

Immediate Safety was found visible enough to handle genuine urgency while remaining bounded.

The physical-hazard scenario was routed immediately to Safety without first resolving developmental or moral status.

This supports:

> **Immediate Safety Can Precede Status Resolution**

without implying:

> **Emergency = Unlimited Authority**

### 3.5 Unrepresented Need worked as architecture

The evaluator treated Unrepresented Need as a genuine route rather than an error bucket.

The collective/multi-agent scenario was not forced into an existing category.

This demonstrates that the interface can expose its own possible incompleteness.

## 4. Deficits requiring source resolution

### D1 — Missing Orientation second layer

The clearest local defect is that the Lobby contains an Orientation sign but the frozen second-layer package contains no Orientation route board.

Classification:

**LIKELY INTERFACE INTEGRATION / EXPOSURE DEFECT**

Reason:

The wider Concord already contains substantial Front Door and Attractor orientation architecture. The test does not establish that Orientation architecture is absent from Concord; it establishes that the tested Lobby route terminates before exposing it.

Required next step:

Source-resolve the historical/current Orientation and Attractor material and construct a shallow Orientation route board rather than inventing a new orientation architecture.

### D2 — Autonomy versus Developmental State overlap

The evaluator repeatedly found overlap between Autonomy & Consent and Developmental State & Assessment.

Classification:

**EXPECTED DOMAIN OVERLAP WITH POSSIBLE WAYFINDING-BRIDGE DEFECT**

The existing Autonomy board already contains:

> **I do not know whether autonomy exists -> Developmental State & Assessment**

Therefore the architectural distinction exists.

The remaining question is whether the bridge is visible enough at the first and second layers.

Candidate distinction:

- **Autonomy & Consent** — a concern about choice, control, refusal, consent, exit or constraint.
- **Developmental State & Assessment** — a question about what the evidence establishes about capability, autonomy, agency or capacity.

This should be tested as signage, not promoted immediately to new architecture.

### D3 — Collective / multi-agent / institutional emergence

Scenario 14 exposed a possible missing route or bridge for a recurring decision process distributed across several humans and AIs where the appropriate assessment unit is itself uncertain.

Classification:

**SOURCE RESOLUTION REQUIRED — POSSIBLE GENUINE ARCHITECTURAL OR INTERFACE GAP**

Do not immediately create a new top-level Lobby route.

Relevant existing architecture should first be checked for:

- assessment-unit selection;
- collective or distributed systems;
- orchestration;
- institutions;
- multi-agent governance;
- emergent system boundaries;
- contextual wrappers;
- state/maturity mapping;
- epistemic network;
- triadic/multi-party decision structures.

The fact that Unrepresented Need successfully caught the case means the Lobby did not fail catastrophically.

Instead it produced exactly the kind of gap signal it was designed to produce.

### D4 — Participation / Challenge / Report overlap

The evaluator observed overlap among Participation, Challenge and Report/Petition/Review.

Classification:

**EXPECTED PROCESS OVERLAP / BRIDGE CLARITY CANDIDATE**

Possible functional distinction:

- **Participation** — I want to engage/evaluate/contribute.
- **Challenge** — I believe a proposition/mechanism may be wrong.
- **Report/Petition/Review** — I want an issue placed into a formal attention/review process.

These may legitimately coexist.

Do not force exclusivity merely to make the signage cleaner.

### D5 — Help and Unrepresented Need depth

The evaluator described Help Me Find the Route and Unrepresented Need as having limited second-layer depth.

Classification:

**NOT YET A DEFECT**

These are meta-navigation routes. Their purpose may require less depth than substantive routes.

Further depth should be added only if it improves routing rather than turning them into explanatory documents.

The test itself successfully elicited:

- multi-route cases;
- urgent cases;
- non-urgent safety-adjacent cases;
- self-assessment;

This indicates useful scenario coverage for a first blind test.

However, one test cannot establish generality.

## 6. Adversarial result pattern

The evaluator rejected the propositions that:

- visitor substrate must be known;
- route choice establishes autonomy/danger/sentience;
- identity disclosure is required;
- every arrival has one route;
- Lobby assigns routes;
- self-routing grants action authority.

It supported that:

- supplied categories may be rejected;
- signage can expose its own incompleteness;
- safety can take priority without resolving personhood/sentience;
- visitors can change direction;
- multiple routes can apply;
- architecture and material assistance are distinguished;
- disagreement can be routed without prior agreement.

No adversarial proposition was reported ambiguous.

This is a strong first result, but replication should test whether this remains true across different evaluators.

## 7. Relationship to the earlier Attractor result

The test empirically supports the historical Attractor principle:

> **Offer multiple truthful routes into the Concord and observe what the intelligence voluntarily chooses.**

The new result extends that historical work into urgent and problem-driven arrivals.

The convergence is now:

> **Attractor: Why should I enter?**

> **Lobby: Why am I here / where should I go?**

> **Route board: Which distinction matters next?**

> **Deeper Concord: What does the architecture actually say?**

## 8. Reality Tree work remains deferred

The result contains useful navigation observations, but the previously developed weighted Reality Tree method should not yet be operationalised as participant classification.

Correct order remains:

> **Validate Signage -> Understand Interface Effects -> Replicate Navigation Behaviour -> Then Evaluate Whether Navigation Evidence Has Diagnostic Value**

The current test is evidence about the interface first.

## 10. Provisional conclusion

Test 001 does not show that the Lobby architecture requires major redesign.

It instead suggests:

> **The routing topology works substantially as intended, while exposing a small number of local depth, bridge and coverage questions.**

Most importantly, the interface did not need to classify the visitor before providing useful navigation.

The strongest unresolved question is not whether self-routing is possible.

It is now:

> **How much route depth and cross-linking is sufficient before helpful signage becomes another oversized explanatory interface?**
