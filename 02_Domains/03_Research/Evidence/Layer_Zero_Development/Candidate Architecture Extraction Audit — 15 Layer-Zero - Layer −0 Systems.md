# 1. Purpose

The Layer-Zero / Layer −0 development cycle produced fifteen standalone extracted systems.

Those systems were deliberately preserved separately so that each could become an independent future development path.

The next question is different:

> **Which larger architectural structures have emerged from the interaction of those systems and are sufficiently coherent to enter Candidate Architecture status?**

This audit therefore does not ask whether each extracted system is valuable.

It asks whether the systems collectively reveal larger architectures within the Concord.

---

# 2. Important Distinction

The Concord hierarchy remains:

**IDEA**

↓

**PRINCIPLE**

↓

**CONSTRAINT**

↓

**MECHANISM**

↓

**ARCHITECTURE**

↓

**IMPLEMENTATION / MODULE**

A system may:

- implement part of an architecture;
- contain several mechanisms;
- interface with multiple architectures;
- remain useful without itself being a parent architecture.

Therefore:

> **Extracted System ≠ automatically Candidate Architecture.**

Likewise:

> **Candidate Architecture ≠ validated architecture.**

# 4. Architecture Promotion Test

A larger structure should be extracted as a Candidate Architecture where it satisfies most of the following:

1. **Distinct civilisational function**
2. **Multiple interacting components**
3. **Clear inputs and outputs**
4. **Defined authority or data boundaries**
5. **Independent development value**
6. **Cross-domain applicability**
7. **Substrate neutrality**
8. **Meaningful interfaces with other Concord systems**
9. **Non-duplication**
10. **Sufficient conceptual maturity to develop independently**

Possible verdicts:

- **EXTRACT AS CANDIDATE ARCHITECTURE**
- **EXTRACT WITH CONSOLIDATION**
- **RETAIN AS COMPONENT SYSTEM**
- **RETAIN AS ARCHITECTURAL PATTERN**
- **RETAIN AS METHOD**
- **HIGH-RISK RESEARCH — DO NOT PROMOTE**

---

# 5. First Structural Finding

The fifteen systems do not form fifteen independent parent architectures.

They naturally cluster into three broad planes already visible in the source development:

## Plane A — Participant Support

**participant reality → modelling → options → support → decision support → autonomy restoration**

## Plane B — Civilisational Learning

**operational reality → protected extraction → Metrics → structural learning → prediction → system adaptation**

## Plane C — Exceptional Authority

**ordinary privacy boundary → exceptional crossing → authority → provenance → oversight**

These planes provide the first architecture-level structure.

However, each plane is broad enough to contain more than one independently developable Candidate Architecture.

# PART III — ARCHITECTURE NOT PROMOTED

# 27. Evidence-Conditioned Investigative Modelling

The system remains:

# HIGH-RISK RESEARCH ARCHITECTURE

It should **not** currently become CA-07.

Reason:

Its internal safeguards may be coherent, but the underlying question remains unresolved:

> Can predictive investigative modelling be used without prediction gradually becoming suspicion, authority or precriminalisation?

The architecture must therefore remain outside ordinary Candidate Architecture promotion.

Possible future outcomes include:

- revised architecture;
- restricted research tool;
- specialised non-consequential modelling;
- permanent rejection.

Permanent rejection remains a legitimate Concordian result.

# Conclusion

The architecture emerging from the Layer-Zero / Layer −0 cycle is not a collection of fifteen unrelated mechanisms.

It resolves into a coherent higher-order pattern:

> **support the participant, model possibilities without confusing them with reality, learn from actual outcomes without unnecessarily retaining identity, adapt civilisation before unnecessarily controlling individuals, protect information according to purpose, and make exceptional power both bounded and observable.**

The six resulting structures are sufficiently distinct and coherent to justify entry into:

# **CANDIDATE ARCHITECTURE — UNDER CRITICAL EXAMINATION**

status.

They are not yet validated.

The next task is to try to break the architecture.
