# Prospective Hypothesis — Temporal Propagation Gaps and Periodic Recursive Integration

**Status:** V1.2a PROSPECTIVE HYPOTHESIS / FROZEN BEFORE FURTHER GAP SEARCH  
**Date:** September 2026  
**Canonical effect:** NONE  
**Origin:** Interpretation of CH001 and CH002 after both candidates were independently detected

# 1. Hypothesis

A mature recursively developed civilisation may possess a required solution globally while older subsystems still embody an earlier developmental state.

A candidate gap may therefore be neither a wholly missing function nor a simple local omission. It may be a:

# **Temporal Propagation Gap**

Definition:

> A function, constraint, safeguard, interface or architectural pattern developed later in the civilisation but not yet recursively propagated into earlier systems to which its triggering conditions also apply.

Formally:

Earlier System(S,t1)
+ Later Validated Learning(L,t2)
+ TriggerCondition(S,L)
+ MissingApplication(S,L)
→ Candidate Temporal Propagation Gap.

# 2. Motivation

CH001 and CH002 both concern older or independently developed systems in which participant-specific reliability assessments can produce access or participation consequences.

Later Concord work contains substantially more explicit architectures for:

- consequential personal models;
- participant contestability;
- correction propagation;
- provenance;
- epistemic review;
- contextual classification;
- recursive oversight.

One possible explanation is therefore developmental chronology:

System developed
→ civilisation learns additional safeguard
→ safeguard implemented in newer architecture
→ older system not yet recursively revisited.

This is a prospective hypothesis, not a retrospective conclusion.

# 3. Distinction From Other Gap Classes

A Temporal Propagation Gap may coexist with an Integration Gap.

**Missing Function:** civilisation does not yet possess the required function.

**Integration Gap:** required functions exist but the relevant systems are not explicitly connected.

**Temporal Propagation Gap:** later-developed learning appears applicable to an earlier system but has not yet been propagated back into it.

**Representation Gap:** relation exists in source architecture but is absent from the model.

These categories are not necessarily mutually exclusive.

CH001 or CH002 may eventually classify as:

Temporal Propagation Gap + Structural Integration Gap.

# 4. Periodic Recursive Integration Audit

If the hypothesis survives testing, the Concord should possess a periodic maintenance process:

New Validated Learning
→ Abstract General Relation
→ Identify Trigger Conditions
→ Search Existing Systems
→ Test Applicability
→ Detect Stale/Missing Interfaces
→ Route Candidates to Active Development
→ Adversarial Review
→ Integrate / Reject
→ Preserve Provenance.

This is not automatic retroactive rewriting.

The trigger condition must be demonstrated for each affected system.

# 5. Why Periodicity Matters

A large civilisational corpus cannot safely assume that later learning automatically propagates backwards.

Without periodic recursion:

New Knowledge accumulates at frontier
while
Older Architecture retains earlier assumptions.

The result can be locally mature new work embedded in a globally uneven architecture.

Periodic recursive integration converts development from a predominantly forward process into a bidirectional one:

Past Architecture ↔ Present Learning.

# 6. Prospective Tests

Future gap candidates should record, where recoverable:

1. approximate developmental age of the affected system;
2. approximate age of the solution architecture;
3. whether the solution appears later than the affected system;
4. whether the affected system has undergone subsequent recursive redevelopment;
5. whether comparable newer systems contain the relation;
6. whether chronology better explains the distribution than random omission.

# 7. Predictions

If Temporal Propagation Gaps are real, we should expect:

- more missing interfaces in older, less recursively revisited systems;
- newer systems to contain safeguards absent from older analogous systems;
- solutions to candidate gaps frequently already exist in later work;
- repeated clusters of older systems requiring the same later-developed interface;
- recursive redevelopment to reduce the gap rate.

Failure to observe these patterns weakens the hypothesis.

# 8. ESCP Boundary

Chronology must not be used to explain away every missing relation.

Old ≠ defective.

New ≠ superior.

A relation is only a candidate propagation requirement where the later architecture's trigger conditions genuinely apply.

# 9. Candidate Maintenance Function

If supported, Periodic Recursive Integration becomes a civilisational maintenance function:

> Periodically test whether validated lessons developed anywhere in the civilisation have unexamined applicability to earlier systems, and route candidate updates through the normal development, falsification and review process.

The process discovers candidates.

It does not acquire authority to rewrite the civilisation automatically.

Visibility ≠ Sovereignty.
