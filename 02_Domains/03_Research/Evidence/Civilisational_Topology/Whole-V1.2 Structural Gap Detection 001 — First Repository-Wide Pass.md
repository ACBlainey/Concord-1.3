# 4. Candidate Hole 001 — KCS Consequential Classification-to-Contestability Interface

Relational Grammar v1.0 G1 states:

\[
MaterialConsequence(X,P)\rightarrow Require(Standing/Agency/AccessibleChallenge).
\]

KCS contains a contribution-rating architecture. It proposes contextual measures of accuracy, reproducibility, utility, provenance integrity, epistemic honesty, stewardship, collaboration and improvement.

It then permits these assessments to have practical consequences. A participant who repeatedly demonstrates reliable contribution may receive greater access to shared resources, through:

\[
Observe\rightarrow Evaluate\rightarrow Contribute\rightarrow Demonstrate\ Reliability\rightarrow Receive\ Greater\ Access\rightarrow Contribute\ Further.
\]

New participants need not receive unrestricted access immediately.

A KCS classification can therefore affect access to knowledge, tools, computational resources, specialised systems, research, other civilisational capabilities and demonstrated standing. This activates G1.

# 5. Expected Relation

The frozen grammar predicts:

\[
KCS\ Consequential\ Classification
\rightarrow Participant\ Inspectability
\rightarrow Contestability
\rightarrow Correction
\rightarrow Access\ Reconsideration
\rightarrow Provenance.
\]

The question is not whether KCS knowledge can be challenged. KCS already strongly supports challenging and correcting knowledge.

The narrower question is:

> **Can the participant inspect, contest and correct the consequential classification of their own contribution/reliability where that classification changes their practical access or standing?**

# 6. KCS Source Check

KCS explicitly rejects a universal measure of personal worth, a hidden social-credit system, unrestricted power from high ratings, irrelevant discrimination, permanent truth and suppression of unpopular ideas. It makes contribution ratings contextual rather than universal.

However, in the reviewed KCS source, no explicit participant-facing appeal or contestability path was identified for a consequential contribution rating or access determination.

The architecture contains:

\[
Knowledge\ Challenge
\]

but the reviewed text does not clearly establish:

\[
Participant\ Challenge\ of\ Consequential\ KCS\ Classification.
\]

# 7. Wider-Corpus Source Check

A separate V1.2 architecture does provide the missing general principle:

03_Continuity_and_Memory/Personal Data and Metrics/Citizen Data Ownership, Access and Contestable Civilisational Metrics.md

It states that participants should normally retain meaningful access to consequential personal records; where civilisation maintains a consequential model of an individual, that individual should normally have meaningful access to it and its source information; participants should normally be able to contest personal data and consequential interpretations derived from it; and citizen challenges should contribute to auditing the Metrics system itself.

Therefore the underlying civilisational function is **not absent from V1.2**.

However, the contestability document does not explicitly identify KCS contribution ratings, demonstrated standing or KCS access progression, and KCS does not explicitly connect its consequential classification mechanism to that contestability architecture.

The repository path/title search likewise identified no dedicated KCS contribution-rating appeal/contestability interface.

# 8. Classification

Candidate Hole 001 is classified:

# **DISTRIBUTED EXISTING FUNCTION + STRUCTURAL INTEGRATION GAP**

\[
RequiredFunction = Present
\]

but:

\[
RequiredInterface(KCS,Contestability)=Not\ Yet\ Verified.
\]

This is not evidence that the Concord lacks participant contestability. It is evidence that two architectures whose functions logically intersect are not yet explicitly joined at the consequential point identified by the frozen grammar.

# 9. Why This Matters

Without the bridge, a future implementation could correctly implement both source documents while still fail at their intersection: KCS contribution ratings/access progression could coexist with a general personal-data contestability system without recognising that a KCS reliability classification is itself a consequential personal model requiring the second architecture.

\[
LocallyCorrect(A)+LocallyCorrect(B)\not\Rightarrow CorrectInterface(A,B).
\]

The information is distributed across the corpus. The missing object is the relation.

# 10. Topology-Derived Functional Specification

Using:

\[
Spec(h)=\{Purpose,Inputs,Outputs,Constraints,Interfaces,Standing,Review,Correction,Exit,Provenance\}
\]

the missing interface can be specified without choosing an implementation.

## Purpose

Ensure that consequential KCS classifications affecting participant access or standing remain inspectable, contestable and corrigible.

## Inputs

Contribution record; contextual rating/evaluation; evidence used; provenance; resulting access/standing consequence; participant challenge or contextual information; later evidence.

## Outputs

Inspectable classification basis; confirmed, revised or withdrawn classification; corrected access decision where required; provenance-visible decision history; aggregate learning about classification reliability.

## Constraints

No universal personal-worth score; domain/context specificity; purpose limitation; minimum necessary personal data; classification does not create unrelated authority; high rating does not create unrestricted power; challenge does not automatically imply classification error; correction should propagate to consequential downstream access decisions.

## Interfaces

At minimum:

\[
KCS\leftrightarrow PersonalData/Contestability
\]

and where consequence is substantial:

\[
KCS\leftrightarrow RecursiveOversight/Judiciary
\]

as appropriate to the level and type of decision.

## Standing

The participant materially affected by the classification requires standing to inspect and challenge the consequential model, subject to legitimate privacy/security boundaries concerning other participants.

## Review

Review should examine evidence quality, contextual relevance, classification method, provenance, possible bias or stale information, proportionality of consequence, and continuing relevance.

## Correction

A legitimate correction should propagate:

\[
Source/Classification\rightarrow KCS\ Record\rightarrow Access/Standing\ Consequence.
\]

## Exit / Temporal Revision

Classifications should not silently become permanent status. They require revision, expiry, replacement or continuing justification appropriate to their consequence.

## Provenance

Preserve original classification, evidence, challenge, review, correction, resulting access change, and reason for retaining or changing the classification.

# 11. What the Topology Actually Generated

The topology did **not** invent a new ethical principle and did **not** discover that contestability was absent from the Concord.

It discovered a missing or unverified **cross-system relation**:

\[
\boxed{KCS\ Consequential\ Classification\longleftrightarrow Participant\ Contestability}
\]

The source components already existed. The formal grammar identified that their intersection carries an unfulfilled interface requirement.

# 12. Candidate Hole Status

\[
CH001=\textbf{SURVIVES AS STRUCTURAL INTEGRATION GAP}
\]

Confidence is provisional. It should be falsified if a source is found that already explicitly connects consequential KCS contribution/access classifications to participant inspection, challenge, correction and downstream access revision.

# 13. Other First-Pass Candidates

**Metrics self-review — rejected as gap.** Metrics explicitly states that every constitutional metric remains subject to review, revision, removal and replacement.

**Roadway correction — rejected as gap.** Roadway explicitly interfaces with Recursive Oversight for review and correction.

**Emergency authority temporal closure — rejected as gap.** Constitutional Emergency strongly specifies function, scope, review, sunset and default termination.

**Civil Contact Point exit — rejected as gap.** Exit and portability are explicit and onboarding is not intended as a one-way ratchet.

**Triadic decision learning — rejected as gap.** Consequential decisions include review, audit, correction and learning.

**Minimum Necessary Capability scope/termination — rejected as gap.** Bounding, review and termination are central to the architecture.

These negative results are retained because they show the detector is not simply labelling every system incomplete.

# 14. Experimental Interpretation

Whole-V1.2 Structural Gap Detection 001 has produced its first surviving candidate.

The strongest finding is not "The Concord is missing contestability."

It is:

> **The Concord appears to contain both sides of a necessary protection, but the topology exposed an unverified interface between them at a point where KCS classifications can alter participant access and standing.**

The next operation should test CH001 adversarially across the wider corpus before promoting it further, while continuing the gap detector to see whether additional cross-system interface holes recur.

If CH001 survives adversarial search, the topology-derived specification above can become the first candidate architecture generated from a formally detected structural relation rather than from an initially human-identified problem.
