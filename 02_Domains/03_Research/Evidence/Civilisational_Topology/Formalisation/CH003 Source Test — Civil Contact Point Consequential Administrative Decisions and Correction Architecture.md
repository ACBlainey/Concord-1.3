# CH003 Source Test — Civil Contact Point Consequential Administrative Decisions and Correction Architecture

**Status:** V1.2a EXPERIMENTAL / PROSPECTIVE CANDIDATE TESTED  
**Date:** September 2026  
**Canonical effect:** NONE  
**Frozen prediction:** `CH003 Prospective Candidate — Civil Contact Point Consequential Administrative Decisions and Correction Architecture.md`

# 1. Question

Does the Civil Contact Point architecture create or mediate participant-specific consequential administrative decisions without an adequate challenge, review and correction path?

# 2. Prospective Outcomes

The candidate was frozen with four possible outcomes:

A. correction relation already explicit locally -> representation gap;

B. decisions external and correction explicitly routed -> no local gap;

C. general correction functions exist elsewhere but Civil Contact Point does not explicitly route to them -> distributed existing function + structural integration gap;

D. consequential decisions exist and no adequate correction architecture exists -> candidate genuine structural gap.

# 3. Dedicated Local Source Search

The Civil Contact Point source was searched for:

- challenge;
- appeal;
- correction;
- review;
- oversight;
- service-access disputes;
- participation-tier disputes;
- record correction;
- identity correction;
- administrative review.

Repository search produced no explicit Civil-Contact-Point-specific challenge/appeal/correction/review/oversight result.

The source itself was then inspected around participation tiers, exit, identity/provenance, vertical interfaces, research questions and failure modes.

# 4. Does the Contact Point Produce Material Consequences?

The source proposes graduated engagement:

Tier 0 Observer  
Tier 1 Registered Contact Participant  
Tier 2 Service Participant  
Tier 3 Active Participant  
Tier 4 Resident  
Tier 5 Citizen / Constitutional Participant.

It states that Tier 2 can access selected Concord services and opportunities, and Tier 3 can participate in research, projects, employment, education and economic activity.

It also explicitly separates:

Contact,
Participation,
Service Access,
Residence,
Citizenship.

Therefore the architecture clearly contemplates participant states associated with materially different practical opportunities.

However, the paper describes these tiers as **exploratory rather than proposed final categories**.

It does not yet clearly assign final authority for progression decisions.

This weakens any claim that the Contact Point itself is already a decision authority.

# 5. Exit Is Strongly Represented

The architecture explicitly asks:

- Can a participant close their contact point?
- Can they transfer records?
- Can they retain access to correspondence?
- Can they maintain a contact point after declining deeper membership?
- Can participation tier decrease?

It states:

**Participation should be capable of decreasing as well as increasing.**

and:

**Onboarding should not function as a one-way ratchet.**

Therefore CH003 cannot be characterised as an exit/reversibility gap.

# 6. Identity and Provenance Are Strongly Represented

The source distinguishes:

Participant Identity
from
Contact Point
from
Current Location
from
Participation Role.

It requires continuity when contact points change and identifies direct interfaces with:

- Continuity;
- KCS;
- Provenance;
- Judiciary;
- Participation;
- Governance.

Thus the architecture already recognises that the Contact Point is not a sovereign self-contained system.

# 7. The Crucial Existing Judiciary Interface

The strongest local evidence against outcome D appears in the Civil Contact Point's own vertical architecture:

**Governance**
→ participation status and service rules.

**Judiciary**
→ disputes concerning identity, notices and rights.

This means the source already anticipates external dispute resolution.

It also asks as an unresolved Governance research question:

**Which institution administers contact status?**

Therefore:

Civil Contact Point
≠ clearly established final decision authority.

Instead, the architecture appears intended as an interface into Governance, Judiciary, Participation and other systems.

# 8. Wider Existing Correction Architecture

The wider Concord contains strong general mechanisms relevant to the candidate.

## 8.1 Personal Data / Contestable Metrics

The participant-data architecture explicitly provides:

- meaningful access to consequential personal records;
- contestation of personal data;
- correction of demonstrably incorrect data;
- correction of consequential interpretations;
- preservation of dispute provenance;
- institutional access controls.

It specifically identifies Judiciary access for:

- disputes over records;
- consequential administrative decisions;
- contested restrictions.

It further states that Judiciary may become an escalation route where a serious data dispute cannot be resolved administratively.

This is directly relevant to Contact Point identity and record functions.

## 8.2 Judiciary

Judiciary V2 provides mechanisms through which individuals and institutions may challenge exercises of power.

It distinguishes ordinary legal, administrative and constitutional disputes.

It explicitly develops practical accessibility, legitimate appeal/review, remedies, correction, standing and the correction of administrative consequences.

Therefore the wider civilisation already possesses substantial correction architecture capable of handling at least some Contact Point disputes.

# 9. What Is Actually Missing?

The dedicated search does **not** support outcome D.

The required function is not absent from the civilisation.

Nor does the evidence cleanly support outcome B, because the Contact Point paper does not provide a sufficiently explicit operational routing path such as:

Contact Point adverse decision
→ notice/reason
→ participant challenge
→ responsible administrative review
→ record correction where applicable
→ Judiciary where unresolved/material
→ downstream service/status update
→ provenance.

Instead the source contains the relevant systems as interfaces and says Judiciary handles disputes concerning identity, notices and rights, but leaves important administrative questions unresolved.

The best current classification is therefore:

# **OUTCOME C — DISTRIBUTED EXISTING FUNCTION + PARTIAL STRUCTURAL INTEGRATION GAP**

with an additional qualification:

# **DEVELOPMENT NOTE / UNRESOLVED ADMINISTRATIVE AUTHORITY**

# 10. CH003 Classification

CH003 survives, but in a narrower form than the original candidate could have implied.

It is **not**:

> Civil Contact Points lack civil dispute resolution.

It is:

> Civil Contact Points contemplate consequential service/status/identity administration and already identify Governance, Judiciary and participant-data/provenance interfaces, but the operational path connecting an adverse Contact Point-related administrative consequence to challenge, correction, escalation and downstream update is not yet explicit.

This is an interface-completion problem.

# 11. Candidate Repair Relation

A minimal topology-derived interface is:

Contact-Point-Related Consequence
→ Legible Notice / Basis
→ Appropriate Participant Challenge
→ Responsible Administrative Review
→ Data/Record Correction Where Applicable
→ Consequence Reconsideration
→ Judicial Escalation Where Material/Unresolved
→ Downstream Update
→ Provenance.

The Contact Point need not own all of these functions.

Indeed, duplicating Judiciary or participant-data architecture locally would be undesirable.

The repair is primarily **routing and interface specification**.
