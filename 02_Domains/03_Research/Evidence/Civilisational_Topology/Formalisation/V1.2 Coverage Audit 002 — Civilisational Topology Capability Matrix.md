**Purpose:** Test whether the proposed Civilisational Topology function is already supplied by existing V1.2 systems, or whether a genuine integration gap remains.

---

# 1. Method

This pass compares major V1.2 precursor systems against ten candidate capabilities of Civilisational Topology.

Scoring is deliberately coarse:

- **0 — absent/not materially evidenced in the reviewed source**
- **1 — indirect or weak support**
- **2 — substantial support**
- **3 — explicit/central capability**

The scores are not quality ratings. They indicate functional coverage in the reviewed documents.

The ten capabilities are:

- **R — Representation:** explicit representation of civilisational state/structure.
- **D — Cross-system dependency modelling:** relationships and shared dependencies across systems.
- **G — Gap detection:** ability to identify missing functions, coverage or unresolved structure.
- **F — Failure propagation:** ability to reason about failures beyond a local component.
- **E — Ethical traceability:** relationship from architecture/action back to ethical or constitutional constraints.
- **P — Participant-need linkage:** participant experience/need can enter the architecture.
- **V — Developmental triggering:** observations/gaps can initiate development or correction.
- **T — Temporal updating:** model/process changes as civilisation changes.
- **S — Self-application:** mechanism can examine its own operation/failure.
- **M — Machine-readable integration:** explicit formal representation intended to integrate the above computationally.

This is an architectural coverage test, not a claim that every document has been exhaustively interpreted.

# 3. Immediate Pattern

The matrix does **not** reveal a civilisation lacking meta-level self-observation.

The opposite is true.

V1.2 contains unusually dense distributed capability for:

- representation;
- correction;
- recursive review;
- participant input;
- development triggering;
- temporal learning;
- failure analysis;
- continuity;
- ethical constraint.

Therefore a Civilisational Topology system must not duplicate these systems.

However, one column is conspicuously weak across almost every precursor:

# **M — Machine-Readable Integration**

Several systems are structured enough to become computationally represented, but none of the reviewed sources appears to maintain one explicit coupled graph connecting the whole set.

This is the clearest candidate integration gap found so far.

# 7. Structural-Hole Test

Define a candidate structural-hole indicator for a node (v):

[
H(v)=sum_{r in R_q} I[
eg path(v,r)]
]

where (R_q) is the set of relation-types expected for the node's class and (I) is an indicator function.

For an architecture node, expected relation classes might include:

- ethical justification;
- legitimate function;
- affected participant;
- dependency;
- failure;
- correction;
- continuity;
- development/replacement.

A high (H(v)) does not prove architectural deficiency.

It identifies where the civilisation should ask:

> Is the relationship genuinely absent, or merely absent from the model?

This explicitly preserves ESCP.

# 8. Dependency-Correlation Test

V1.2 already warns that apparent plurality can conceal common dependency.

Topology permits this to become computable.

For two supposedly independent mechanisms (a) and (b), define their dependency sets:

[
D(a),D(b)
]

A simple overlap measure is:

[
J_D(a,b)=
rac{|D(a)cap D(b)|}
{|D(a)cup D(b)|}
]

High overlap does not prove correlated failure, but it identifies claimed redundancy that deserves examination.

A more developed model can weight dependencies by criticality and failure correlation.

This directly operationalises the existing Concord question:

> **Independent with respect to which plausible failure?**

# 12. Temporal Topology

The coupled model should not be static.

Let:

[
mathbb{C}_t=(V_t,E_t,L_t,W_t,P_t)
]

where (P_t) records provenance/status.

Then:

[
Delta mathbb{C}_{t_1,t_2}
]

can identify:

- newly created nodes;
- removed nodes;
- changed dependencies;
- increased concentration;
- reduced redundancy;
- newly unsupported functions;
- repaired gaps;
- newly introduced failure pathways;
- architecture that persists after its generating need disappears.

This connects topology directly to the existing Concord principle that past legitimacy does not guarantee present legitimacy.
