# Canonical Migration Plan 001 — Civilisational Developmental Topology and Levelling Architecture

**Status:** V1.2a MIGRATION PREPARATION / CANDIDATE OUTPUT
**Date:** September 2026
**Canonical effect:** NONE
**Purpose:** Fix the intended canonical placement, interfaces, document family and integration sequence before any V1.2 file is changed.

# 1. Placement Decision

Repository inspection supports the primary canonical home:

**02_Epistemic_and_Research/Civilisational_Developmental_Topology/**

This is preferable to Governance, Coordination/Economy or Continuity/Memory because the system's primary function is epistemic-developmental: represent required civil functions, evidence about their state, dependencies and maturity; propose development priorities; test predictions; and correct the map when wrong.

It does not possess civil authority merely because its model is accurate.

This placement is consistent with the existing Epistemic and Research README, which states that epistemic/research architecture informs wider Concord systems but does not acquire independent constitutional authority.

# 2. Existing Canonical Owners That Must Not Be Absorbed

## KCS — 03_Continuity_and_Memory

KCS remains owner of civil knowledge state, provenance, preservation, retrieval, status, reuse and the future operational dependency representation.

CDTLA consumes and structures dependency knowledge; it does not replace KCS.

## Constitutional Metrics / Civilisation Clock — 04_Coordination_and_Economy

The existing Metrics architecture already contains civilisation-clock cycles, priority architecture, state assessment, task allocation, evaluation and state update.

CDTLA supplies topology, maturity and dependency evidence into that cycle. It does not create a second Clock.

## Constitutional Core

The topology may trace ethical/constitutional constraints but cannot create or supersede them.

## Governance / Judiciary / Oversight

CDTLA may identify a defect or bottleneck. Legitimate authority, adjudication, review and constitutional adoption remain with their existing owners.

## Active Development

The development environment remains the place where candidate solutions are developed and tested. CDTLA determines evidence-based development need/order; it does not erase the development pipeline.

# 3. Canonical Interface Model

Constitutional / Ethical Constraints
→ Required-Function Topology
↔ KCS Knowledge + Dependency State
↔ Metrics / Civilisation Clock
↔ Civil State Map
→ Development Queue
→ Active Development
→ Independent Evaluation / Review
→ Canonical Adoption where legitimate
→ KCS + State Map update
→ Clock recomputation.

Correction can enter at every stage.
