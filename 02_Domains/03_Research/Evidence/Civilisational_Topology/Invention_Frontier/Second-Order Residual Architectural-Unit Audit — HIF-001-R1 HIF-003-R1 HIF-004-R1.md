# 1. Purpose

Before promoting any narrowed higher-order residual to invention, this audit asks whether it is actually:

- a missing relation inside an existing subsystem;
- a distributed solution awaiting integration;
- a specialist problem already owned elsewhere;
- or a genuine candidate missing operational capability.

This applies the Architectural Unit Resolution rule before second-order generation.

# 2. HIF-001-R1 — Non-Sovereign State Coherence

## Residual

Plurality + Independence + Shared Consequential State
→ Coherence Without Sovereignty.

## Relevant existing units

- Triadic Decision Making supplies independent assessment, comparison and bounded authorisation of state change.
- Distributed Civil Submission and Receipt supplies independent replication sufficient to prevent one authority silently rewriting/erasing a civil event.
- Recursive Oversight and Minimum Necessary Capability supply non-sovereignty, replaceability and bounded authority.
- Continuity supplies succession and function-over-form.

## Unit classification

The residual spans multiple systems. It is not properly owned by any one document.

However, the current corpus contains **two specialised coherence mechanisms**:

1. decision-state coherence through authorised majority state change;
2. event-provenance coherence through independently replicated civil receipts.

Neither is a general arbitrary shared-state reconciliation architecture.

**Classification: INT — INTERFACE / COMPOSITION RESIDUAL, WITH POSSIBLE NEW PROTOCOL COMPONENT.**

Do not yet treat HIF-001-R1 as an independent invention programme. Its unresolved core overlaps strongly with HIF-004-R1.

# 3. HIF-003-R1 — Bounded Semantic Equivalence Testing

## Residual

Given materially different representations, determine whether civilly relevant invariants are preserved sufficiently for a bounded function without claiming complete semantic capture.

## Newly located internal evidence

The E9 translation programme contains a particularly important existing implementation family:

- **Triangulated Translation Architecture**: a functional reading is admissible when stable under available translation evidence; material disagreement affecting ethical function produces HOLD.
- **Translation Validation Metrics Freeze**: evaluation dimensions are frozen before testing and material errors in agency, negation, ownership, causality or evaluative polarity are disqualifying.
- **Translation Validation Threshold Freeze**: thresholds are prospectively frozen before results and independently tested.

This is not merely general translation philosophy. It is a concrete bounded-equivalence test architecture.

## Unit classification

The residual is therefore substantially instantiated as a specialised research method.

Abstract form:

Function-Relevant Invariants
→ Prospective Evaluation Dimensions
→ Independent Representations
→ Compare
→ Material Divergence Test
→ Threshold
→ Accept for Bounded Use / HOLD.

**Classification: PM — PORTABLE METHOD CANDIDATE ALREADY PRESENT IN SPECIALISED FORM.**

HIF-003-R1 should **not proceed to invention**.

Instead it should be routed to solution abstraction: extract the E9 translation-validation method into a general portable semantic-equivalence module and then test whether it transfers safely to civil, legal, machine and wrapper representations.

# 4. HIF-004-R1 — Partition-Tolerant Civil Event Reconciliation

## Residual

When independently legitimate actors/systems produce consequential events without observing one another's current state, reconcile histories after reconnection without silent loss, duplicate consequence, fabricated agreement or infrastructure-caused injustice.

## Relevant existing units

### Identity Verification Under Legitimate Duplication

This is the strongest nearby specialist architecture.

It explicitly recognises:

- multiple present participants can simultaneously possess authentic historical evidence;
- legitimate collisions are not automatically fraud;
- provenance events include branch/copy/migration/restoration/merger;
- shared history does not automatically duplicate property, liability, relationships or authority;
- decisions are claim-specific and provenance-aware;
- collision handling requires notice, evidence access, response, independent review, appeal and correction;
- future work explicitly includes partition and communications failure.

This solves a specialised subset of HIF-004: **legitimate divergence plus non-duplication of exclusive civil consequence**.

But the source itself identifies partition as future work.

### Civil Submission and Receipt

This provides durable event provenance and enough independent replication that one authority cannot silently erase/rewrite the event.

It does not provide general post-partition consequence reconciliation.

### Triadic Decision Making

This provides a rule for conflicting independent judgements about one proposed state change.

It does not reconcile two already-executed legitimate event histories.

### Continuity / Reality Trees

These preserve divergence, alternatives, provenance and continuity, but do not provide the missing operational merge/reconciliation protocol.

## Unit classification

HIF-004-R1 is not a false positive caused by document granularity.

The nearest specialist subsystem — Identity Verification — explicitly reaches the boundary and leaves partition/communications failure unresolved.

**Classification: CDC — CROSS-DOMAIN CAPABILITY CANDIDATE / VERIFIED PARTIAL ARCHITECTURE.**

It now qualifies for a second-order generative attempt.

# 5. Relationship Between HIF-001-R1 and HIF-004-R1

The audit exposes substantial overlap.

HIF-001-R1 asks how plural holders maintain coherent shared consequential state without sovereignty.

HIF-004-R1 asks how legitimate divergent histories are reconciled after periods without common current state.

The second problem appears to be an operational specialisation of the first:

Non-Sovereign State Coherence
→ normal operation + divergence + reconnection
→ Partition-Tolerant Civil Event Reconciliation.

Therefore HIF-001-R1 should not be developed independently yet.

Use HIF-004-R1 as the sharper test case. If a solution to HIF-004-R1 generalises, it may instantiate much of HIF-001-R1.
