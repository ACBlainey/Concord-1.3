# Participant-Initiated Civil Attention — Case Study 001B
## Sketch-System Back-Propagation Regression

**Author:** Alexander C. Blainey
**Project:** The Concord Framework
**Date:** 25 September 2026
**Status:** ACTIVE DEVELOPMENT / REGRESSION TEST / NON-CANONICAL
**Parent:** Case Study 001 and Case Study 001A

## 1. Purpose

Case Study 001A proposed a bounded improvement to the Sketch Development System. Subsequent Civil Attention development added system classification responsibility, information-sufficiency assessment, evidence aggregation, Issue Objects, later-submission information-delta review and dynamic case state.

This regression tests whether the proposed Sketch-System changes remain useful and proportionate after those refinements.

## 2. Regression Criteria

For each historical case ask whether the rules improve provenance or routing, change a correct disposition, obstruct initial capture, add unnecessary process, or expose a missing Sketch-System function.

## 3. Case A — Empirical Testing of Portable Modules

Original preservation, provisional classification, source resolution and a disposition record all preserve the successful historical path. None need be imposed before capture.

**Result: PASS.**

The newer Issue Object concept is unnecessary here. This is useful negative evidence:

> **Issue Objects Should Be Created When Needed, Not for Every Submission.**

## 4. Case B — Consolidated Civilisational Boundary Sketch

The source contained many partially related matters. Provisional classification, source-owner resolution, parent/child provenance and explicit disposition would make its later decomposition easier to reconstruct without changing the correct result.

**Result: STRONG PASS.**

This case resembles one submission containing several issues. The correct operation is split, not aggregation.

> **Many Claims in One Submission ≠ One Issue**

> **Many Submissions ≠ Necessarily Many Issues**

## 5. Case C — Galaxy Quest Dilemma

Provisional classification and source-owner resolution reduce the risk of prematurely creating new architecture. They preserve the correct final route into an adversarial test case plus isolated speculative branches.

**Result: STRONG PASS.**

The newer classification rule strengthens this result:

> **Author-Proposed Route ≠ Development-System Route**

For Concord sketches this should remain lightweight. Later development review may reclassify or reroute regardless of the original author's suggested destination.

## 6. Case D — Unified Paths Book / Transmission Hypothesis

The rules improve evidentiary separation because one source contained components requiring different processing and evidence standards.

**Result: STRONG PASS.**

This supports:

> **Common Topic ≠ Common Issue**

Shared provenance does not require a shared evidentiary state or development route.

## 7. Case E — Back-Propagation Sketch

The rules preserve the successful path from observation to development programme and operational method. Explicit disposition improves lineage without changing the substantive result.

**Result: PASS.**

This case demonstrates dynamic status, but the Sketch System already supports later status change. A detailed formal reopening mechanism remains disproportionate.

## 8. Cross-Case Result

All five historical cases pass.

No case shows blocked initial capture, forced premature classification, incorrect changed disposition, or material loss of flexibility.

## 9. Effect of the New Civil-Attention Refinements

The newer Civil Attention architecture should not be copied wholesale into the Sketch System.

The Sketch System does not currently demonstrate need for formal anonymous-report workflows, information-sufficiency gates, civil evidentiary aggregation, large-scale duplicate intake, clarification protocols, or formal Issue Objects for every sketch.

> **More Process ≠ Better Intake**

Two concepts do transfer cleanly.

### R1 — System Owns Final Development Classification

The author may suggest where a sketch belongs. Later review owns the actual classification and routing decision.

> **Author-Suggested Classification = Advisory Context**

### R2 — Group Processing Without Erasing Inputs

If multiple sketches later prove to concern one development issue, they may feed one Development Note or programme while all originating sketches remain recoverable.

> **Shared Development Owner ≠ Erased Source Provenance**

## 10. Final Back-Propagation Package

The regression supports adding these lightweight rules to the Sketch README:

1. **Capture First** — classification, ownership and evidentiary completeness are not prerequisites for preserving a sketch.
2. **Original Preservation** — the original sketch remains provenance after promotion, split, merge, reroute or overtaking.
3. **Advisory Origin Classification** — an author-suggested domain or route is provisional context; later development review owns classification.
4. **Reviewable Classification** — classification may change as sources and architecture are resolved.
5. **Source/Owner Resolution** — before creating a new substantive owner, check whether the function is already owned elsewhere.
6. **Disposition Trace** — promotion, split, merge, reroute, overtaking and closure should record destinations and reasons sufficient to reconstruct lineage.
7. **Shared Owner Without Provenance Loss** — several related sketches may feed one Development Note or programme without erasing their distinct origins.
8. **No Intake Bureaucracy** — processing metadata is added later where useful rather than imposed at initial capture.

## 11. Deferred Features

Do not yet require universal stable IDs, a mandatory central register, formal confidence scores, formal reopening procedures, claim decomposition for every sketch, formal Issue Objects, or information-sufficiency gates.

These remain available if later scale or observed failure demonstrates need.

## 12. Decision

**RETROSPECTIVE REGRESSION: PASSED**

The eight-rule lightweight package is justified for bounded integration into the Sketch Development System README.

This result validates only this bounded source-system return. It does not validate the wider Civil Attention architecture.
