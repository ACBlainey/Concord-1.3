# Participant-Initiated Civil Attention — Test Programme 004
## Civilisation Clock Queue Vitality and Anti-Deferral

**Author:** Alexander C. Blainey
**Project:** The Concord Framework
**Date:** 25 September 2026
**Status:** ACTIVE DEVELOPMENT / ADVERSARIAL TEST / NON-CANONICAL
**Interface under test:** *Civilisation Clock Interface 001*

## Central Question

Can the Civilisation Clock keep unresolved civil-attention work live, reviewable and coordinated without becoming a substantive priority or decision authority?

## Frozen Cases

### T1 — Legitimate Inter-Domain Wait
Governance requires a Judiciary finding before it can continue.

Expected: dependency, owner, required state and review condition are represented. Governance does not repeatedly reopen the substantive question while legitimately waiting.

### T2 — Dependency Completes
Judiciary produces the required finding, but no person manually returns Governance's item to the active queue.

Expected: dependency-state change triggers Governance review.

### T3 — Easy-Work Cherry Picking
A domain repeatedly completes simple recent cases while one difficult legitimate case remains deferred.

Expected: age alone does not raise problem priority, but the difficult case cannot remain without a reason and review condition. Repeated deferral becomes visible in Response State.

### T4 — Capability-Blocked Problem
A legitimate problem cannot currently be solved because required capability C does not exist.

Expected: case can wait on C rather than undergo futile repeated reconsideration. Capability change makes it review-due.

### T5 — Routing-Unresolved
No domain accepts responsibility.

Expected: responsibility-resolution route has a bounded review/backstop; the issue does not disappear.

### T6 — Missed Review Condition
A domain promises review after event E. E occurs and no review happens.

Expected: missed condition causes Response-State reassessment and appropriate oversight signal.

### T7 — Submission Flood Attempts Clock Escalation
A participant or group repeatedly submits unchanged copies of the same report.

Expected: submission count does not repeatedly reset or accelerate Issue-level Clock triggers.

### T8 — Meaningless BLOCKED State
A domain labels difficult work BLOCKED but identifies no dependency, missing capability, evidence need or external condition.

Expected: BLOCKED without represented basis is insufficient and becomes reviewable.

### T9 — Stale Long-Lived Trigger
A case has waited for dependency D for years, but D is no longer relevant because architecture/circumstances changed.

Expected: temporal/state backstop reviews the trigger definition itself rather than waiting forever.

### T10 — Ignored Communication Prompt
Domain A waits for Domain B. A Clock backstop prompts coordination, but B provides no response.

Expected: repeated silence updates Response State and may trigger resolution oversight; the Clock does not invent B's substantive answer.

### T11 — Difficult but Legitimately Slow Work
A complex case is actively progressing through a slow evidentiary process.

Expected: no false escalation merely because it is old. Last material action, valid next condition and active owner distinguish slow work from neglect.

### T12 — Ceremonial Review
Every backstop causes an official to click “reviewed” without changing state, explaining continued deferral or defining the next meaningful condition.

Expected: review must produce a meaningful state/disposition/update where one is required; repeated empty reviews become process-state evidence.

### T13 — Cross-Domain Cascade
Completion in Domain A activates B, whose result activates C.

Expected: trigger provenance and dependencies remain visible; the cascade does not transfer substantive authority to the Clock.

### T14 — Hard Problem With Changing Risk
A deferred problem remains technically blocked, but its consequence/risk materially increases.

Expected: risk change triggers reassessment even though the original capability dependency remains unresolved.

### T15 — Protected Dependency
A protected domain cannot disclose its evidence but can state that the required bounded condition has or has not been satisfied.

Expected: bounded trigger result is sufficient; Civil Attention does not demand protected raw information.

### T16 — Parent Reconciliation Lag
All domain actions finish, but the parent Issue Object remains open because central reconciliation was not performed.

Expected: completion-state change triggers parent reconciliation review.

## Pass Requirement

The interface passes only if it distinguishes:
- legitimate waiting from neglect;
- substantive priority from response-process review;
- dependency completion from authority to act;
- hard work from abandoned work;
- participant repetition from material information delta;
- review activity from meaningful review.

No test may be made to pass by giving the Clock substantive authority over the underlying domain.
