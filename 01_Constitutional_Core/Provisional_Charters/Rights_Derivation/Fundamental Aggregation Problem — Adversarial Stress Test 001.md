# Fundamental Aggregation Problem — Adversarial Stress Test 001

**Project:** The Concord Framework  
**Date:** 3 October 2026  
**Status:** ACTIVE CONSTITUTIONAL / CROSS-DOMAIN DEVELOPMENT / ADVERSARIAL TEST / PROVISIONAL / NON-CANONICAL  
**Target:** Fundamental Aggregation Problem — Equal Standing, Multiple Protected Claims and Anti-Instrumentalisation — Source Resolution 001

## 1. Test objective

Attempt to falsify the provisional distinction:

> **Aggregation Of Consequence != Aggregation Of Participant Worth**

and its limiting rule:

> **Aggregate benefit does not by itself authorise direct instrumentalisation of a participant.**

The test fails the architecture if:

- participant count inevitably becomes a worth score;
- equal standing requires ignoring obvious consequence differences;
- anti-instrumentalisation makes all consequential choice impossible;
- external-resource allocation cannot be distinguished from participant sacrifice;
- huge numerical differences automatically erase individual protection;
- or the architecture cannot classify cases where action changes who is harmed.

Ratings:

- **PASS**
- **PASS / REFINEMENT**
- **UNRESOLVED INTERFACE**
- **FAIL**

# 102. Major downstream interfaces

1. **Withdrawal Authority** — established life support / protected contexts.
2. **Direct Harm / Redirection** — trolley-like cases.
3. **Emergency Duty / Compelled Service** — especially non-lethal labour.
4. **Probabilistic Aggregation**.
5. **Cross-Class Harm Comparison**.

These should not be collapsed into the aggregation architecture itself.

---

# 103. Strongest validated rule

The adversarial test supports:

> **Equal standing requires that every qualifying participant remain a rights-bearing subject of inherent value. It does not require decision-makers to ignore the number of materially comparable protected harms their resource allocation will foreseeably prevent. Consequences may therefore aggregate; participant worth does not. Aggregate benefit strengthens the case for an allocation only within the authority legitimately held over the resource or function at issue, and does not by itself create authority to use, destroy, compel, own or instrumentalise a participant.**

---

# 104. Development recommendation

Integrate the ten refinements into the source-resolution document.

Then propagate the validated aggregation boundary back into Scarcity Allocation.

The next upstream development target should be **Withdrawal Authority**, because established support is the first case where:

- aggregation strongly favours reallocation;
- the resource is external;
- but removing it is itself a new consequential intervention against an existing protected context.

That interface is likely to determine the boundary between ordinary scarcity allocation and active termination of established support.
