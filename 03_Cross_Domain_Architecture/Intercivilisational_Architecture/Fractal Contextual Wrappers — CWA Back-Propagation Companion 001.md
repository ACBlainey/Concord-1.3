## Purpose

This companion returns source-relevant refinements exposed during portable CWA development.

Many refinements were not invented by the portable module. Wider source resolution recovered them from existing Concord architecture. The purpose is therefore to make the primary contextual-wrapper representation better connected to its own source family.

> **Source Recovery → Consolidation, not false invention**

The parent wrapper kernel remains unchanged.

## 1. Precedence Resolution Router

Where nested or overlapping contexts produce material conflict, do not use a universal winner rule.

Route:

**Conflict**
→ **Material conflict check**
→ **Decision-object decomposition**
→ **Protected constraint**
→ **Protective threshold**
→ **Emergency state**
→ **Function / competence / decision jurisdiction**
→ **Explicit legitimate priority rule**
→ **Adjudicative/jurisdictional routing**
→ **Minimum temporary action where independently justified**
→ **Legitimate resolver or unresolved state**
→ **Termination / reversion / review**

Valid unresolved outcomes include:

**UNKNOWN / DISPUTED / REQUIRES EXTERNAL RESOLUTION**

The router is an interface. It does not itself adjudicate.

## 2. Decision-object decomposition

Before asking which actor/context has priority, identify the actual decisions in conflict.

> **Apparent Actor Conflict May Be Multiple Decision Objects**

Different functions may legitimately own different components.

## 3. Authority topology separation

Where material, distinguish:

- reporting/coordination;
- competence;
- responsibility;
- decision jurisdiction;
- protective authority;
- functional priority;
- review;
- escalation.

> **Reporting Authority ≠ Decision Competence**

> **Decision Competence ≠ Universal Decision Sovereignty**

> **Priority of Function ≠ Superiority of Participant**

## 4. Permission before authority

A function does not automatically require authority.

First ask whether the required interaction can be supplied through legitimate bounded permission.

> **Functional Permission ≠ Contextual Authority**

> **Permission to Use ≠ Authority to Control**

> **Capability to Enter ≠ Permission to Enter**

## 5. Function-derived permission

Where existing Concord permission architecture applies:

**Legitimate Function**
→ **Genuine Functional Need**
→ **Reasonably Necessary Interaction**
→ **Minimum Necessary Permission**
→ **Function-Bounded Use**
→ **Function Completion / Basis Ends**
→ **Permission Terminates**

The detailed permission architecture remains owned by Fractal Permission Architecture / Minimum Necessary Capability.

The wrapper records and exposes the relevant permission relationship rather than absorbing those systems.

## 6. Action-specific permission and provenance

Where ambiguity is material, record:

- participant;
- action;
- target/space;
- function;
- legitimate basis;
- conditions;
- time/termination;
- provenance.

One permitted action does not imply another.

Permission basis may differ materially even where the physical action is similar.

## 7. Nested-context inheritance

> **Nesting ≠ Automatic Rule Inheritance**

> **Reachability ≠ Permission**

> **Physical Accessibility ≠ Normative Accessibility**

A parent or child rule is inherited only where the applicable architecture establishes that relationship.

Monotonic/additive clearance chains may exist in specific domains, but CWA must not infer them universally.

## 8. External-resolution discipline

CWA may detect a conflict without possessing authority to resolve it.

Where the source architecture supplies a legitimate resolver, record and route to that resolver.

Where it does not:

**UNKNOWN / DISPUTED / REQUIRES EXTERNAL RESOLUTION**

is a valid result.

> **Conflict Detection ≠ Adjudication Authority**

## 9. Responsibility continuity

Overlapping contexts, emergency priority or temporary protective action must not erase:

- responsibility;
- provenance;
- review;
- affected-party state;
- correction routes.

Temporary functional priority does not dissolve other legitimate responsibilities.

## 10. Termination and residual state

Context termination requires more than declaring return to surrounding norms.

Where material, inspect:

- residual permissions;
- credentials/access;
- delegated or assumed capability;
- data retained;
- active processes;
- temporary authority;
- outstanding responsibility/remedy;
- external effects.

Terminate or route each according to its legitimate basis.

> **Context End ≠ Automatic Residual-State Erasure**

## 11. Representation reconciliation

Human-readable, machine-readable and operational context representations should refer to the same underlying state.

Where they diverge:

**Detect discrepancy → preserve evidence → determine authoritative source through legitimate process → correct affected representations → record provenance**

Do not assume a machine-readable or human-readable declaration is reality merely because it is formally encoded.

## 12. Context-sensitive legibility

Boundary/transition legibility should scale with:

- material difference;
- risk/consequence;
- participant role;
- voluntariness;
- familiarity;
- practical ability to understand/avoid;
- temporal urgency.

A wrapper grammar should not create information overload.

## 13. Externality boundary

The parent rule remains:

> **Contextual Boundary ≠ Externality Boundary**

Where consequences cross a legitimate boundary, CWA exposes the externality interface.

Responsibility, jurisdiction and remedy remain separately resolved.

Where CBERRM applies, CWA may route a candidate consequence into that mechanism without manufacturing jurisdiction.

## 14. ESCP source-resolution safeguard

Before classifying an apparent wrapper deficit as missing Concord architecture:

1. inspect the local wrapper source;
2. inspect declared neighbouring architectures;
3. inspect source-grounded functional owners;
4. preserve UNKNOWN where evaluation space remains incomplete;
5. distinguish local under-representation from corpus-level absence.

CWA development itself demonstrated this twice through precedence and function-derived permission source recovery.

> **Local Unresolved State ≠ Global Architectural Absence**

## 15. Authority boundary

This companion does not give CWA authority to:

- determine constitutional legitimacy;
- invent consent;
- create property rights;
- manufacture jurisdiction;
- certify permission merely because a function benefits from it;
- convert expertise into authority;
- create emergency sovereignty;
- adjudicate unresolved legal conflicts;
- override domain-specific rules;
- make local context sovereign.

## 16. Relationship to source family

**Fractal Contextual Wrappers** owns bounded-context legibility.

**Fractal Permission Architecture / Minimum Necessary Capability** own detailed permission/capability justification and bounding.

**Functional Priority / Protective Authority** owns function-specific priority and protective relationships.

CWA connects these where a contextual wrapper requires them. It does not collapse them into one system.
