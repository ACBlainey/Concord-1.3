## 3. Clock Trigger Relations

The Clock Companion Extension establishes a general trigger grammar, but these relations are not encoded as claims that the Clock owns the target systems.

For KCS purposes the important relation is:

**recorded state/event/capability/dependency change → Clock trigger evaluation → legitimate domain review/action.**

The Clock may trigger:
- development reconsideration;
- threat review;
- cold-knowledge relevance/retrieval;
- voluntary participant wake-candidate review.

**Trigger ≠ authority.**

## 4. Operationalisation State

For subsequent State Map use, a function may now be described along four separable operationalisation dimensions:

- C — CONCEPT state;
- M — MECHANISM state;
- T — TEST state;
- I — INTEGRATION state.

Suggested values:

**PRESENT / PARTIAL / ABSENT-CANDIDATE / UNKNOWN / DISPUTED / NOT-APPLICABLE**

with mechanism/test/integration additionally allowing **UNDEVELOPED** or **NOT-TESTED** where useful.

This is additive metadata, not a replacement for existing presence/maturity states.
