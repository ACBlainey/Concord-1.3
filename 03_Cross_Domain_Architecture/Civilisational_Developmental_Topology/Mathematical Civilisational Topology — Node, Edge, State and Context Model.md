# Abstract

The Civilisational Developmental Topology requires a formal representation that distinguishes required civilisational functions from documents, system owners from functions, structural presence from developmental maturity, and genuine gaps from unresolved interfaces or upstream dependencies.

This paper defines the initial mathematical schema for that representation.

The model is deliberately weaker than a universal ontology. It does not claim that civilisation can be completely reduced to a graph, nor that a machine-readable representation becomes authoritative merely because it is formal.

Instead it provides a corrigible common grammar for answering operational questions:

- What function is being represented?
- At what topological level?
- Which ethical or constitutional requirements constrain it?
- Who legitimately owns or supplies it?
- What does it depend upon?
- What depends upon it?
- In which contexts is it applicable?
- What is its current presence and maturity state?
- What evidence supports that state?
- What happens if it fails?
- How can corrections propagate?
- Which development is blocked by which prerequisite?

The formal model is intended to become the grammar used by the Knowledge Control System dependency representation, Civil State Map and Civilisation Clock development-order interface.

# 1. Formal Objective

Let the developmental civil model at time (t) be:

[
mathcal{C}(t)=langle N,E,O,I,K,M,X,F,P,Tangle
]

where:

- (N) = architectural nodes;
- (E) = typed relations;
- (O) = ownership/supply relations;
- (I) = interfaces;
- (K) = dependency and criticality state;
- (M) = maturity/sufficiency state;
- (X) = context and applicability;
- (F) = failure/correction/recovery relations;
- (P) = provenance/evidence;
- (T) = temporal/state-transition information.

This object is a **civil self-model**, not the civilisation itself.

[
mathcal{C}(t) 
eq Civilisation(t).
]

Every element must therefore be corrigible.

# 2. Node Model

A node represents a required civilisational function or persistent architectural capability.

For node (n):

[
n=langle id,l,f,r,dangle
]

where:

- (id) = stable identifier;
- (l) = topological level;
- (f) = function;
- (r) = ethical/constitutional provenance;
- (d) = description/boundary.

A node is not automatically a document, institution or implementation.

## 2.1 Stable IDs

Initial canonical IDs should preserve the experimental derivation:

- L0-01 … L0-10
- L1-01 … L1-12
- L2-01 … L2-14
- L3-01 … L3-16

The identifiers are stable references, not rankings.

If later evidence changes a node, version the definition rather than silently changing its historical meaning.

## 2.2 Node classes

Initial classes:

- ROOT_FUNCTION
- CROSS_SYSTEM_FUNCTION
- WHOLE_CIVILISATION_FUNCTION
- META_COHERENCE_FUNCTION

Additional classes require explicit justification.

## 2.3 Node admission

A proposed new node must be:

1. necessary for a consequential civil function;
2. irreducible to an existing node or relation;
3. persistent rather than one-off;
4. operationally distinguishable;
5. ethically/constitutionally traceable;
6. not merely a renamed scale instance;
7. not merely a maturity deficit;
8. not merely an implementation mechanism.

- (n_i) = source;

- REQUIRES
- DEPENDS_ON
- SUPPLIES
- OWNS
- INTERFACES_WITH
- CONSTRAINS
- REVIEWS
- CORRECTS
- PROPAGATES_TO

- RECOVERS
- PRESERVES
- ESCALATES_TO
- DELEGATES_TO
- OBSERVES
- MEASURES
- EVIDENCES
- ALTERNATIVE_TO

Typed relations should be directional where direction matters.

A relation must not imply authority unless authority is explicitly represented and independently legitimate.

# 8. Ownership Model

For capability (q), owner candidate (s), and context (c):

[
Owns(s,q,c)
]

is valid only where ownership is supported by legitimate architecture.

Ownership may be:

- PRIMARY
- DISTRIBUTED
- DELEGATED
- INTERFACE_SUPPLIED
- DISPUTED
- UNKNOWN

The topology cannot create ownership merely by assigning a label.

[
TopologyAssignment 
otRightarrow LegitimateAuthority.
]

# 9. Interface Model

An interface (i) is:

[
i=langle producer,consumer,capability,scope,state,failure,correctionangle.
]

Interface satisfaction for requirement (r) requires:

[
IS(r,c)=I_1land I_2land...land I_8
]

where:

- I1 legitimate external owner;
- I2 owner capability exists;
- I3 interface sufficient;
- I4 authority bounded;
- I5 dependency visible;
- I6 failure/unavailability represented;
- I7 correction/review propagation where material;
- I8 no hidden sovereignty/unreviewable monopoly.

If any material condition is unresolved, interface satisfaction should not be assumed.

---

# 10. Context Model

A context record may include:

[
c=langle domain,consequence,participants,authority,scale,environment,substrate,modeangle.
]

Applicability:

[
A(n,r,c)in{TRUE,FALSE,UNKNOWN,DISPUTED}.
]

This allows the same architecture to be adequate in one deployment and inadequate in another.

Context should be explicit for consequential maturity claims.

# 11. Presence State

Node/function presence is represented separately from maturity.

Initial presence vocabulary:

- PRESENT_EXPLICIT
- PRESENT_DISTRIBUTED
- INTERFACE_SATISFIED
- PARTIAL
- DEPENDENCY_BLOCKED
- CANDIDATE_ABSENT
- UNKNOWN
- DISPUTED
- NOT_APPLICABLE

A node may combine presence descriptors where useful, for example:

**PRESENT_DISTRIBUTED + PARTIAL_INTEGRATION.**

Machine encoding should preserve components rather than relying on ambiguous prose labels.

# 12. Maturity Model

Let:

[
M(n,c)=langle m_1,...,m_kangle
]

rather than assuming a single maturity number.

Initial maturity dimensions include:

- bounded scope;
- legitimate/non-self-justifying authority;
- temporal revision/exit/termination;
- contestability/correction/repair;
- participant standing/agency;
- asymmetry/anti-capture compensation;
- effective access;
- function-over-form/replaceability;
- recursive review;
- provenance/learning.

Additional domain-specific dimensions may be attached where necessary.

A scalar maturity score should not be introduced until evidence demonstrates that the dimensions can be combined without hiding consequential differences.

---

# 13. Sufficiency

Define:

[
Q(n,c)
]

as the minimum maturity condition sufficient for node (n) in context (c).

Then:

[
Sufficient(n,c)iff M(n,c)succeq Q(n,c).
]

The relation (succeq) need not be numeric.

It means that all materially applicable requirements meet the necessary threshold.

Civilisational levelling therefore seeks:

[
orall n,c_{active}: Sufficient(n,c)
]

subject to explicit UNKNOWN and DISPUTED states.

# 14. Dependency Model

A dependency record is:

[
d=langle dependent,owner,capability,materiality,criticality,alternatives,state,evidenceangle.
]

Dependency state may include:

- ACTIVE
- SATISFIED
- DEGRADED
- BLOCKING
- FAILED
- ALTERNATIVE_AVAILABLE
- UNKNOWN
- DISPUTED
- SUPERSEDED

A dependency can exist without currently blocking development.

This distinction is essential.

---

# 15. Criticality

Criticality should remain multidimensional.

Relevant factors include:

- consequence of failure;
- number of dependents;
- importance of dependents;
- availability of alternatives;
- recovery difficulty;
- reversibility;
- time sensitivity;
- shared/correlated exposure.

A highly connected dependency is not automatically the most critical.

---

# 16. Failure Representation

Failure is not a single state.

For system/function (n), represent where relevant:

- local failure;
- interface failure;
- owner failure;
- dependency failure;
- correlated failure;
- degraded operation;
- silent failure;
- stale-state failure;
- correction failure;
- recovery failure.

Failure edges should support tracing:

[
Failure(n_i)ightarrow Consequence(n_j).
]

This enables continuity and resilience analysis without requiring a new central resilience authority.

---

# 17. Correction Propagation

If object or state (x) is corrected, the graph should identify materially affected dependents.

Represent:

[
Correction(x)ightarrow Review(y)
]

only where the dependency is materially relevant.

Correction propagation should be selective.

The goal is neither no propagation nor indiscriminate global re-audit.

---

# 18. Provenance Model

Every consequential topology claim should be capable of linking to evidence.

A provenance record should include:

- source;
- claim;
- extraction/interpretation;
- author/agent where known;
- date/version;
- confidence;
- validation state;
- supersession state.

The Knowledge Control System is the natural persistent owner of this information.

The topology should reference it rather than create a competing provenance store.

[
S_t.

[

Relations may include:

- PRECEDES_MATERIALLY
- FOLLOWS_MATERIALLY
- INDEPENDENT_FOR_CONSEQUENCE
- ORDER_UNKNOWN_BUT_IMMATERIAL
- ORDER_UNKNOWN_AND_MATERIAL
- CONCURRENT
- BRANCHES_FROM
- RECONCILES_WITH
- CORRECTS
- SUPERSEDES

The Civilisation Clock remains owner of developmental/temporal ordering. The topology supplies the state/dependency objects upon which ordering operates.

# 20. Architectural Unit Resolution Algorithm

Given apparent deficit (g):

1. identify local observation;
2. abstract required capability (q);
3. identify applicable context (c);
4. search known owners;
5. search distributed supply;
6. test interfaces;
7. inspect upstream dependencies;
8. inspect current maturity;
9. source-resolve outside the initial search area;
10. classify.

Possible result:

[
Class(g)in
{
TRUE_ARCHITECTURAL_GAP,
DEVELOPMENTAL_GAP,
INTEGRATION_GAP,
DEPENDENCY_BLOCKED,
REPRESENTATION_GAP,
SATISFIED,
UNKNOWN,
DISPUTED
}.
]

No repair should precede this classification where consequence warrants source resolution.

# 21. Development Target Selection

Let candidate target (n) have priority state:

[
P(n)=langle H,E,D,B,L,U,Rangle
]

where:

- (H) = harm/consequence severity;
- (E) = current exposure;
- (D) = dependency criticality;
- (B) = upstream blockage;
- (L) = legitimate development leverage;
- (U) = uncertainty;
- (R) = intervention reversibility/risk.

Initially, (P(n)) is a structured vector, not a scalar.

Development selection should be explainable from its components.

# 22. Upstream Bottleneck Rule

For candidate deficit set (G), find capability owners (O(G)).

If multiple consequential deficits depend upon one legitimate owner (u), and (u) is below required maturity:

[
exists g_1,...,g_k:
g_iightarrow u
]

then (u) becomes an upstream development candidate.

This does not override high-harm independent deficits.

The selection process must compare both.

# 26. Machine-Readable Representation Boundary

This schema is designed to permit later machine encoding.

However:

[
FormalSchema 
eq ValidatedOntology.
]

Machine readability should follow sufficient semantic stabilisation.

Initial implementation should test a bounded subset before attempting whole-corpus conversion.

A machine-readable graph must preserve:

- UNKNOWN;
- DISPUTED;
- provenance;
- context;
- versioning;
- uncertainty;
- distributed ownership;
- alternative interpretations.

A representation that forces every uncertainty into one definitive edge would be less faithful than the prose architecture it replaces.

---

# 27. Versioning

Node and edge definitions require versioning.

Recommended pattern:

- stable ID;
- definition version;
- effective date;
- prior definition;
- reason for change;
- evidence;
- compatibility note.

Deleting a node should normally mean **SUPERSEDED/RETIRED**, not historical erasure.

# 29. First Implementation Test

Do not encode all L0-L3 nodes immediately.

Select a bounded test set containing:

- one mature explicit node;
- one distributed node;
- one interface-satisfied node;
- one dependency-blocked node;
- one partial node;
- one disputed or unknown state if available.

Encode their:

- owners;
- interfaces;
- dependencies;
- maturity;
- evidence;
- failure relations;
- development state.

Then test whether the representation can reproduce the source-grounded classification without hiding uncertainty.

Only after this test should whole-topology population begin.

# 31. Relationship to the Earlier Multilayer Model

The earlier developmental work represented civilisation as:

[
C(t)=Eotimes Fotimes A(t)otimes X(t)otimes R(t)otimes G(t)
]

where ethical, functional, architectural, exposure/failure, resilience and generative layers interact.

The present graph model does not replace that representation.

It operationalises part of it.

The tensor-style expression describes interacting civilisational dimensions.

The typed graph describes identifiable functions, relationships and states that can be inspected and updated.

The two representations should remain mutually informative rather than being collapsed prematurely.

# Conclusion

Civilisational Developmental Topology becomes operational only when its concepts can be represented consistently enough to survive reuse.

This model provides that first formal grammar.

Its central object is not a hierarchy of documents.

It is a corrigible graph of required functions, legitimate owners, bounded interfaces, dependencies, contexts, maturity, failures, evidence and state transitions.

The next development is therefore not another abstraction level.

It is the first companion upgrade to an existing canonical system:

> **KCS Companion Upgrade 001 — Operational Dependency and Change-Propagation Architecture.**

That upgrade should use this schema to determine whether the Knowledge Control System can maintain the live dependency state required by the Civil State Map and Civilisation Clock without becoming a central authority or universal database.
